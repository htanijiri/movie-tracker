# movie-tracker ― 開発の記録

## 1. このアプリは何か
見たいと思った映画を忘れず、見るまで・見た後まで管理する、自分のための映画リスト。
映画を「知った瞬間」から「見た後」までを1か所で扱う Web アプリ。

### 出発点となった要望（2026-10-07）
- 映画館で本編の前に流れる予告を見て「これは見たい」と思った作品がいくつかあったのに、本編を見終わる頃には作品名を思い出せなくなっていた。後日、予告を見直して特定することになった。
- この経験から、次のことを自分用に管理したくなった。
  - 見たい映画、見た映画、見送った映画
  - 劇場で見たいのか、サブスクで配信されたら見たいのか
  - どこで知ったか（予告、CM、SNS など）
  - 見た日、見た場所、感想
  - 劇場で見逃した作品が配信されたかどうか
- 既存の映画レビューサービスが「見る → 評価する」を中心にしているのに対し、「自分がその映画をどう知り、どの媒体なら見たいと思ったのか」を重視する。
- ソースコードは GitHub で公開し、将来は一般の利用者にも使えるサービスにすることを想定する。

## 2. 主要な設計判断と、その理由

### なぜ映画館の中での入力を前提にしないのか
画面の光が周囲の迷惑になり、撮影や録音と誤解されるおそれもある。スマホでも腕時計型の端末でも同じ。そのため「映画館の中では何もしない」を基本にし、見終わってから登録する作りにした。将来の予告特定の機能も、「気になった予告が何本あったか」だけを覚えておき、あとで候補から探す、という考え方に立つ。

### なぜ「見たい」を3つに分けるのか
「絶対に映画館で見たい」と「配信されたら見たい」と「今回は見ない」では、その後の行動が違う。区別せずに残すと、リストを見返したときに判断をやり直すことになる。最初の段階では 劇場／サブスク／見送る の3つに絞り、レンタルなどの区分はあとから足せるようにした。

### なぜ「見送る」も記録するのか
予告を見て「これは見ない」と判断したことも、あとで「あの予告の映画は何だったか」を思い出す手がかりになる。

### なぜ TMDb だけを使い、スクレイピングをしないのか
ソースコードを公開する前提なので、プログラムからの取得を正式に認めているサービスだけを使う。一般向けの Web ページを勝手に読み取る方法は、利用規約と倫理の面で公開の妨げになる。TMDb は開発者向けの API を公開しており、日本向けの配信状況（JustWatch 提供）も取得できる。

### なぜ映画の情報を自分の DB にコピーしないのか
映画そのものの情報（TMDb が持つ）と、利用者ごとの情報（自分が持つ）を分けるため。自分の DB には TMDb の ID と、一覧を表示するための最小限の情報だけを置く。TMDb の利用条件（長期間の保持の禁止）にも合う。

### なぜ Cloudflare（Workers ＋ D1）＋ React Router なのか
計画の時点では Next.js ＋ Vercel ＋ PostgreSQL が候補だったが、デプロイ先を Cloudflare にすると決めたため、Cloudflare 前提で選び直した。D1 はアプリと同じアカウントで完結し、接続情報の管理が要らない。React Router は Cloudflare が公式に対応しており、開発サーバーが本番と同じランタイムで動く。詳しくは [TECH_NOTES.md](TECH_NOTES.md) の「技術選定」。

### なぜ利用者が1人なのに Google ログインを入れるのか
公開 URL に置く以上、他人に書き換えられないための入口が必要。合言葉1つで守る案もあったが、将来の一般公開にそのまま発展させられる Google ログインを選び、当面は許可したアカウントだけが使えるようにした。データは最初から利用者ごとに分けて保存する。

### なぜ「近日公開」を公開日順に並べないのか
予告で見た作品を探すのが目的なので、映画館で予告が流れるような話題作が先に出るほうが見つけやすい。実データで比べると、公開日順では再上映の旧作や小規模な作品が先頭に並び、目当ての作品は何ページも先になった。注目度の高い順にすると、先頭の20件に入った。

### なぜ一覧の裏で、映画の情報を取り直すのか
一覧は、表示を速くするために、保存済みの最小限の情報（タイトル、ポスター、公開日）で表示している。一方で TMDb の利用条件は、取得したデータを長いあいだ持ち続けることを禁じている。「配信を待つ」映画は何か月も詳細を開かないことがあるので、一覧を開いたついでに、古くなった情報を少しずつ取り直す。画面の表示は待たせない。

### なぜ初期データを自動で入れないのか
タイトルから自動で作品を特定すると、同名や続編のある作品で誤った登録が起きる。自分で登録すれば、完成したアプリの使い心地の確認を兼ねられる。

## 3. 開発の時系列
### 第1期：設計とMVP（2026-10-07 〜）
- 2026-10-07：計画書をもとにキックオフ。未決事項（デプロイ先、保存先、フレームワーク、認証、公開範囲、ライセンス、自動デプロイ、一覧から探す機能、評価の形式、初期データの入れ方）をチャットで決め、仕様書 000〜007 を作成。
- 2026-10-08：仕様書の確認で、公開 URL を取得済みの独自ドメインのサブドメインにすることを決定。映画のおすすめ機能（見た記録から好みに合う作品を挙げる）を、フェーズ2以降の候補に追加。
- 2026-10-08：仕様書 000〜007 に合意をもらい、実装を開始。基盤（React Router v8、D1、テスト、GitHub Actions）、Google ログイン、映画を探す、映画詳細、見たい登録、きっかけ、見た記録、トップページと一覧までを実装した。自動テストは175件。実装中に、React Router が v8 になっていたこと、近日公開の並び順、日本の公開日の扱い、古い情報の取り直しなどを見直した（各仕様書の「実装中に変えたこと」）。
- 2026-10-09：本番のデータベース（D1）を作成し、Cloudflare Workers に初回のデプロイを行った。公開 URL で、クレジットのページの表示と、未ログイン時の保護を確認した。
- 2026-10-10：実際に使ってみての改善を2つ行った（仕様書 008）。「見た」を押しても、先に選んでいた「劇場で見たい」などが選ばれた見た目のまま残っていたのを、「見た」が選択中に見えるように直した。一覧の視聴済みのカードに、どこで見たか（劇場、サブスク、レンタル・購入、その他）のラベルを足した。
