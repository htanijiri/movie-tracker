# 007 トップページと一覧

- 状態：完了
- 依存：004、005、006

## 👤 ユーザーが確認するところ

### 何のための機能か
アプリを開いたときに、「次に何を見るか」と「最近何を見たか」がひと目で分かるようにする。

### できるようになること
- トップページ「次に何を見る？」に、3つの区分が上から並ぶ。
  - 🎬 **劇場で見たい**：公開日が早い順（上映が先に終わりそうなものが上）。公開前の映画には「◯月◯日公開」と出る。
  - 📺 **サブスク待ち**：登録が新しい順。
  - ✅ **最近見た**：見た日が新しい順に5本。見た日、場所・サービス名、★が出る。
- どの区分でも、映画ごとにポスター、タイトル、自分の状態、きっかけ（1行）が一緒に表示される。押すと詳細に進む。
- 「リスト」画面で、登録したすべての映画を、すべて／劇場で見たい／サブスク待ち／視聴済み／見送り に切り替えて見られる。「見送り」にした映画はここで見返せる。
- 何も登録していない区分には、「まだありません」と「映画を探す」への案内が出る。
- 画面の下に、ホーム／探す／リスト のメニューが常に出る。

### データの扱い
- トップページと一覧は、自分のデータベースに保存した内容だけで表示する（開くたびに TMDb へ問い合わせない）。そのため、タイトルやポスターは、最後に詳細を開いた時点のものが表示される。

### 使い方の流れ
1. アプリを開くと、トップページが表示される。
2. 「劇場で見たい」「サブスク待ち」から、次に見る映画を決める。
3. 見たら、映画を押して詳細を開き、見た記録を付ける（仕様書 006）。

### やらないこと
- サブスク待ちの映画が配信開始したことの表示（Phase 2）。配信状況は、詳細を開いたときにだけ確認できる。
- 「そろそろ上映終了」「来週公開」などの案内（Phase 2）。
- 好みに合う映画のおすすめ（「今公開中でおすすめは？」「配信中の邦画で好みに合うものは？」など。Phase 2 以降）。今回ためる記録（★、感想、劇場／サブスク／見送りの区分、きっかけ）が、そのときの材料になる。
- 並び順の変更、絞り込み、リスト内の検索。
- 見た本数などの集計。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 初期データ（BRIEF の9作品）は、完成後にユーザーが自分でアプリから登録する | 使い心地の確認を兼ねられ、別の作品が誤って登録される心配がない。登録用のコマンドは作らない |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの：
  - **初期データの登録**：BRIEF の9作品を、「探す」から自分で登録する（劇場で見たい／サブスクで見たい／見送る、予告で知った作品にはきっかけも）。先日見た作品には見た記録を付ける。
  - 登録後、トップページの3つの区分と「リスト」の「見送り」に、意図したとおりに並んでいる。
  - 登録から記録までの操作が、日常的に使える手軽さになっている（使いたくなるかどうかは、本人にしか判断できないため）。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [x] AC1：`/` の loader が、`WANT_TO_WATCH`＋`THEATER` を公開日の昇順（公開日が NULL のものは最後）、`WANT_TO_WATCH`＋`STREAMING` を `created_at` の降順、`WATCHED` を `watched_at` の降順（同日は `updated_at` の降順）で最大5件返す（自動テスト）
- [x] AC2：`SKIPPED` の映画はトップページのどの区分にも出ない（自動テスト）
- [x] AC3：loader は TMDb を呼ばない（fetch のモックが呼ばれないことを確認）。タイトル・ポスター・公開日は `movies` テーブルから JOIN で取得する（自動テスト）
- [x] AC4：他の利用者の映画は出ない（自動テスト：2ユーザー分のデータ）
- [x] AC5：カードに、ポスター、タイトル、状態のラベル、きっかけの1行（005 の `formatDiscovery`）が含まれる。視聴済みのカードには `YYYY/MM/DD`、場所・サービス名、★の数が含まれる（自動テスト）
- [x] AC6：公開日が今日（`Asia/Tokyo`）より後の映画には「M月D日公開」、公開日が NULL の映画には「公開日未定」が付く（自動テスト）
- [x] AC7：各区分が0件のとき、「まだありません」と `/search` へのリンクが出る（自動テスト）
- [x] AC8：`/list?filter=all|theater|streaming|watched|skipped` が、それぞれの条件の映画をすべて返す。不正な `filter` は `all` として扱う。`all` は `updated_at` の降順（自動テスト）
- [x] AC9：「最近見た」が6件以上あるとき、「すべて見る」（`/list?filter=watched`）が出る（自動テスト）
- [x] AC10：`movies` のスナップショットが30日より古い映画があっても、一覧は古い内容のまま表示し、エラーにならない（取り直しは詳細を開いたときに行う）（自動テスト）
- [x] AC11：開発サーバーで、劇場・サブスク・視聴済み・見送りの映画を登録し、トップページと一覧に仕様どおり並ぶ（手動：Claude。実際の TMDb のデータで、登録から表示までを通して確認する）
- [ ] AC12：ユーザーが初期データを登録し、意図したとおりに並ぶ。日常的に使える手軽さになっている（手動：ユーザー）

### 設計方針
- **クエリ**：`listForHome(db, userId, today)` と `listByFilter(db, userId, filter)` を `app/lib/db/user-movies.ts` に置く。`movies` と INNER JOIN。トップページは区分ごとに1クエリ（合計3つ）を `db.batch` でまとめる。
- **インデックス**：`user_movies(user_id, status, preferred_medium)`、`user_movies(user_id, watched_at)`。000 のマイグレーションに含める。
- **カード**：`MovieCard` コンポーネントを 002 の検索結果（縦型のグリッド）と共有せず、こちらは横型（左にポスター、右に文字）にする。BRIEF の「映画情報と自分の情報を同時に確認できる」に合わせる。
- **下部メニュー**：000 の共通レイアウトに置いたものを使う。現在の画面を `aria-current="page"` で示す。
- **「劇場で見たい」の並び**：公開日の昇順にすることで、公開から時間が経って上映終了が近い作品が上に来る。公開終了の案内（Phase 2）の代わりを、並び順だけで果たす。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 保存済みのスナップショットで表示 | ○ | 開くたびに登録本数ぶん TMDb を呼ばずに済み、表示が速い |
| 開くたびに TMDb から取得 | × | 登録本数に比例して外部への呼び出しが増え、Workers の制限にも掛かりやすい |
| 初期データをコマンドで登録 | × | チャットで決定（ユーザーが自分で登録する） |
| 見送りもトップページに出す | × | 「次に何を見る？」の画面に、見ない映画は不要。一覧で見返せれば足りる |

### 検証方法
- 自動テスト：D1 にテストデータを入れ、loader の戻り値とレンダリング結果を確認する。
- 手動確認（Claude）：AC11。登録 → きっかけ → 見た記録 → トップページ、という一連の流れは、実データとブラウザで通して確かめる。

### 実装中に変えたこと（2026-10-08）
- **古くなった映画の情報を、一覧を表示した裏で少しずつ取り直すようにした（AC3・AC10 に関係）。**
  - 一覧の表示そのものは、これまでどおり保存済みの内容だけで行い、TMDb を待たない。
  - 応答を返したあとに、取得から30日を超えた情報を、古い順に3本まで TMDb から取り直す。誰のリストにも入っていない映画の古い情報は消す。
  - 理由：TMDb の利用条件は、データを6か月を超えて保持することを禁じている。「サブスク待ち」に入れたまま詳細を開かない映画は、放っておくと何か月も古い情報を持ち続けることになる。「取り直しは詳細を開いたときだけ」という当初の設計では、これを防げなかった。
- 公開済みの映画には「YYYY/MM/DD 公開」を出す（AC6 は公開前と未定だけを決めていた）。公開からどのくらい経ったかの目安になる。
- 絞り込みの種類の定数は `app/lib/list.ts` に置いた。サーバー専用のファイル（`*.server.ts`）に置いたら、画面側から参照していたため本番のビルドが失敗した（開発サーバーでは気づけなかった）。
- AC12（初期データの登録と使い心地）は、ユーザーの手動確認として残る。
- **2026-10-10 追記**：視聴済みのカードの表示（「どこで見たか」のラベルを足し、下の行を「見た日 ・ 場所」にする）は、仕様書 008 で変更した。AC5 のうち「場所がなければ視聴方法を出す」は、008 の AC7 に置き換わった。
