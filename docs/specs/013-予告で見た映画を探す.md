# 013 予告で見た映画を探す

- 状態：ドラフト
- 依存：006、008、011

## 👤 ユーザーが確認するところ

### 何のための機能か
このアプリの出発点の問題、「映画館の予告で気になった映画のタイトルを、本編を見終わる頃には忘れている」を解決する。映画館の中では何もせず、見終わったあとに「気になった予告が何本あったか」だけを記録し、あとで候補の予告を見ながら特定する。

### できるようになること
- **「見た」の記録に「気になった予告」を足す。** 視聴方法が「劇場」のときだけ、`なし／1本／2本／3本／4本以上` から選べる（選ばなくてもよい）。日付と映画館は、見た記録のものを使う。あとから編集で付け足すこともできる。
- **探し終わっていない分は、トップページに出る。**
  - 例：`🎞 予告を探す：10/4 映画館X「映画A」の上映前（3本中 あと2本）`
  - 押すと、その日の「予告を探す」画面に進む。
- **「予告を探す」画面**
  - その日に予告が流れていそうな映画を、候補として縦に並べる。候補は、見た日の1か月前から半年後までに日本で公開（予定）の映画を、注目度の高い順に。見た映画そのものは除く。
  - 各候補に、ポスター・タイトル・公開日と、`▶ 予告を見る`・`これだった 👍`・`違う` のボタンがある。
  - `▶ 予告を見る`：その場で予告が再生される。
  - `これだった 👍`：その場で `劇場で見たい／サブスクで見たい／見送る` を選ぶと、リストに登録される。きっかけ（映画館の予告・見た日・映画館・「映画A」の上映前）は自動で入る。すでにリストにある映画なら、登録はそのままで、きっかけが空のときだけ自動で入る。
  - `違う`：その候補は一覧から消え、次の候補が繰り上がる。押し間違えたときは、画面の下の「「違う」にした◯本を戻す」で戻せる。
  - 見つけた映画は、画面の上に「見つけた予告」として並ぶ。
- **探し終わる条件**：見つけた本数が「気になった予告」の本数に達したら、トップページから消える。「4本以上」の場合や、途中であきらめる場合は、「探すのを終える」ボタンで終えられる。

### 使い方の流れ
1. 映画館では何もしない。見終わったら、「気になった予告」が何本あったかだけ覚えておく。
2. アプリで、見た映画に「見た」を付ける。視聴方法「劇場」を選び、「気になった予告」の本数を選んで保存する。
3. あとで（家などで）トップページの「🎞 予告を探す」を押す。
4. 候補の予告を見ながら、「これだった 👍」か「違う」を押していく。見つけたら、劇場で見たいかどうかを選んで登録する。

### データの扱い
- 候補と予告は TMDb から取得する（これまでと同じ）。予告は、再生ボタンを押したときだけ YouTube につながる。
- 費用はかからない。

### やらないこと
- 映画館ごとの上映スケジュールや、実際にその回で流れた予告の情報（データの取得元がない）。
- 他の利用者が登録した予告の情報を使うこと（計画書のフェーズ4）。
- AI や音声による予告の認識。
- 劇場以外（配信など）で見た記録への「気になった予告」の入力。
- 見た記録とは別の「映画館に行った記録」の画面。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 「気になった予告」の本数は、劇場で見たときの「見た」の記録に足す | 入力が最小限で、新しい入力画面が増えない。日付と映画館は見た記録のものを使える |
| 候補は一覧で並べ、その場で予告を見て「これだった／違う」を押す | 画面を行き来しなくてよい。計画書の例（ポスター、予告を見る、これだった、違う）に近い |
| 「これだった」を押したら、その場で登録する。きっかけは自動で入る | 見つけたその場で、劇場で見たいかどうかを決められる |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの：
  - 実際に映画館で見た映画で、「気になった予告」を記録し、「予告を探す」で目当ての予告を見つけられるか（候補の並びが実際に役立つかは、本人にしか判断できないため）。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [ ] AC1：見た記録のフォームで、視聴方法が「劇場」のときだけ「気になった予告」の選択肢（なし／1／2／3／4本以上）が出る。`save-watched` で `trailerCount`（空、0〜4。4は「4本以上」）を受け付け、`user_movies.trailer_count` に保存する。範囲外は 400。劇場以外で保存したときは NULL にする（自動テスト）
- [ ] AC2：トップページの loader が、探し終わっていない予告探し（`watched_medium = THEATER`、`trailer_count >= 1`、見つけた本数 < 本数（4は上限なし）、終了していない）を、見た日の新しい順に返す。他の利用者のものは返さない（自動テスト）
- [ ] AC3：`/trailers/:tmdbId`（`:tmdbId` は見た映画）の loader が、TMDb の `/discover/movie` を `region=JP`、`with_release_type=2|3`、`release_date.gte=見た日−30日`、`release_date.lte=見た日+183日`、`sort_by=popularity.desc` で1〜3ページ取得し、見た映画・「違う」にした映画・「これだった」にした映画を除いて、最大20本を返す。予告探しの対象でない記録は 404（自動テスト）
- [ ] AC4：「予告を見る」は、`/trailers/video/:candidateId` から予告の YouTube の ID を取得して、その場で再生する（`/movie/{id}/videos` を1回呼ぶ。選び方は仕様書 003 と同じ）。予告がなければ「予告が見つかりませんでした」（自動テスト：取得部分。再生はブラウザで確認）
- [ ] AC5：`intent=match` で、候補の映画を `medium`（THEATER／STREAMING／NONE）で登録し、きっかけ（`THEATER_TRAILER`、見た日、見た記録の映画館、`「<見た映画のタイトル>」の上映前`）を入れ、「これだった」を記録する。候補がすでにリストにあれば、登録の状態は変えず、きっかけが空のときだけ入れる（自動テスト）
- [ ] AC6：`intent=reject` で「違う」を記録し、候補から消える。`intent=restore-rejects` で、その予告探しの「違う」をすべて取り消す（自動テスト）
- [ ] AC7：見つけた本数が本数に達したら、トップページに出なくなる。`intent=close` で、本数に達していなくても終えられる（自動テスト）
- [ ] AC8：見つけた映画は、画面の上の「見つけた予告」に並ぶ（自動テスト）
- [ ] AC9：TMDb が応答しないときは、案内を出し 500 にならない（自動テスト）
- [ ] AC10：開発サーバーで、劇場で見た記録に本数を付け、トップページから「予告を探す」に進み、予告の再生・「これだった」での登録・「違う」・「戻す」・「探すのを終える」が動く。幅 375px で崩れない（手動：Claude）
- [ ] AC11：実際に映画館で見た映画で、目当ての予告を見つけられる（手動：ユーザー）

### 設計方針
- **データ**（マイグレーションを1つ追加。列とテーブルの追加だけ）：
  - `user_movies.trailer_count`（INTEGER、NULL 可、0〜4 の CHECK）、`user_movies.trailer_hunt_closed_at`（TEXT、NULL 可）。予告探しは「劇場で見た記録」1つにつき1つなので、見た記録の行に持たせる（計画書の TheaterVisit を別のテーブルにしない）。
  - `trailer_finds`：`id`、`user_id`、`visit_tmdb_id`（見た映画）、`candidate_tmdb_id`、`result`（`match`／`reject`）、`created_at`。`UNIQUE(user_id, visit_tmdb_id, candidate_tmdb_id)`。`movies` は参照しない（「違う」にした候補のスナップショットを持たないため）。
  - 見た記録を取り消したとき（`unwatch`）・リストから消したときは、その予告探しの `trailer_finds` も消す。
- **画面**：`/trailers/:tmdbId`（ログイン必須のレイアウトの下）。候補の行は `TrailerCandidate` コンポーネント。「予告を見る」は `useFetcher().load("/trailers/video/:id")`（リソースルート）で予告の ID を取得し、`TrailerPlayer` を再生状態で表示する。「これだった」は押すと3つのボタンに切り替わる。
- **TMDb**：`listTrailerCandidates(visitDate, page)`（`client.server.ts`）、`getTrailer(tmdbId)`（`/movie/{id}/videos`、`include_video_language=ja,en,null`、`pickTrailer`）。1回の表示で3回、予告の再生で1回。
- **トップページ**：`listOpenTrailerHunts` の結果を、お知らせの下・区分の上に「🎞 予告を探す」として出す。
- **見た記録のフォーム**：`WatchedFields` に、視聴方法が劇場のときだけ「気になった予告」のラジオボタン（なし／1〜3／4本以上）を出す。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 見た記録の行に本数を持たせる | ○ | チャットで決定。1回の鑑賞＝1つの見た記録なので足りる |
| 計画書どおり TheaterVisit を別のテーブルにする | × | 見た記録と二重の入力になる。他の利用者との共有（フェーズ4）を作るときに分ける |
| 候補ごとに詳細を取得して、予告の ID を最初から持つ | × | 1回の表示で TMDb を20回以上呼ぶことになる。押したときに1回取るほうが軽い |
| 候補を「近日公開」タブの一覧で代用する | × | 見た日を基準にできず、「違う」で絞り込めない |

### 検証方法
- 自動テスト：TMDb をモックし、loader・action・リソースルートを直接呼ぶ。トップページの表示、見た記録のフォームの選択肢を確かめる。
- 手動確認（Claude）：AC10。予告の再生と、ボタンの切り替えの動きはブラウザで確かめる。
- 手動確認（ユーザー）：AC11。候補が実際に役立つかは本人にしか判断できないため。
