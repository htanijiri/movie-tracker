# 004 見たい映画の登録（劇場で見たい／サブスクで見たい／見送る）

- 状態：合意済み
- 依存：003

## 👤 ユーザーが確認するところ

### 何のための機能か
気になった映画を忘れないように残す。同じ「見たい」でも、「映画館で見たい」のか「配信されたら見たい」のか「今回は見ない」のかを区別して残す。

### できるようになること
- 映画詳細の画面の上のほうに、3つのボタンが並ぶ。押した時点で登録される（入力や確認の画面はない）。
  - 🎬 劇場で見たい
  - 📺 サブスクで見たい
  - ❌ 見送る
- 登録済みの映画では、選んでいるボタンが強調される。別のボタンを押すと、その場で切り替わる（例：劇場で見逃したので「サブスクで見たい」に変える）。
- 「登録を取り消す」で、その映画を自分のリストから消せる。きっかけや感想も一緒に消えるので、消す前に確認が出る。
- 「見送る」にした映画も記録として残り、一覧（仕様書 007）で見返せる。予告で見て「これは見ない」と判断したことを残しておける。

### 使い方の流れ
1. 「探す」から映画の詳細を開く。
2. 3つのボタンのどれかを押す。これで登録は終わり。
3. きっかけ（仕様書 005）を書きたいときは、そのまま下の欄に入力する。

### やらないこと
- 「レンタルでも見たい」「どれでもいい」の区分（BRIEF で「Phase 1 では3つから始めてよい」とされているため。データの入れ物は用意しておき、あとから増やせる）。
- 「気になる（まだ決めていない）」という保留の状態（予告を特定する Phase 3 で使う想定）。
- 「探す」の一覧の上から直接登録するボタン（ポスターを並べる表示では押し間違えやすいため、詳細画面で登録する）。
- 見たい度合いの順位付けや並べ替え。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [ ] AC1：未登録の映画で「劇場で見たい」を POST すると、`user_movies` に `status=WANT_TO_WATCH`、`preferred_medium=THEATER` の行ができる。「サブスクで見たい」は `WANT_TO_WATCH`/`STREAMING`、「見送る」は `SKIPPED`/`NONE`（自動テスト）
- [ ] AC2：登録済みの映画で別のボタンを POST すると、同じ行の `status` と `preferred_medium` だけが変わり、`discovery_*` と `created_at` は変わらず、`updated_at` が更新される。行は増えない（自動テスト）
- [ ] AC3：同じ内容を2回 POST しても行は1つのまま（`UNIQUE(user_id, tmdb_id)` と upsert）（自動テスト）
- [ ] AC4：「登録を取り消す」を POST すると、その利用者のその映画の行だけが消える。他の利用者の行は消えない（自動テスト）
- [ ] AC5：`status=WATCHED` の映画に対して3つのボタンの POST を送っても、視聴記録（`watched_*`、`rating`、`review`）は消えず、`status` も `WATCHED` のまま、`preferred_medium` だけが変わる（自動テスト）
- [ ] AC6：`preferred_medium` に3種類以外の値を POST すると 400 で、DB は変わらない（自動テスト）
- [ ] AC7：登録時に、`movies` のスナップショットがなければ TMDb から取得して作る（一覧でタイトルとポスターを出せるようにするため）（自動テスト）
- [ ] AC8：詳細画面の HTML で、選択中のボタンに `aria-pressed="true"` が付く。未登録ではどれにも付かない（自動テスト）
- [ ] AC9：JavaScript が無効でも、ボタンの POST とリダイレクトで登録できる（自動テスト：action を直接呼ぶ）
- [ ] AC10：ブラウザでボタンを押すと、画面の再読み込みなしで強調が切り替わる（手動：Claude）

### 設計方針
- **action**：`/movies/:tmdbId` の action に `intent`（`set-medium`／`remove`）を持たせる。005・006 も同じ action に `intent` を足す。入力の検証は action の先頭で行う。
- **状態の対応**：画面の3択 → `(status, preferred_medium)`。`WATCHED` のときは `status` を変えない（AC5）。`WATCHED` の画面では3つのボタンを出さず、見た記録（006）を表示する。
- **クエリ**：`app/lib/db/user-movies.ts` に `setPreferredMedium(db, userId, tmdbId, medium)`、`removeUserMovie(db, userId, tmdbId)`、`getUserMovie(db, userId, tmdbId)`。すべて `userId` 必須。
- **画面**：React Router の `useFetcher` で送信し、楽観的に強調を切り替える。取り消しは `<dialog>` で確認する（JavaScript 無効時は確認用の画面を挟まず、そのまま消える動作でよい）。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| ボタンを押した時点で保存 | ○ | 「入力を極力少なくする」という BRIEF の方針 |
| フォームに入力して「保存」を押す | × | 操作が増える |
| `status` を持たず `preferred_medium` だけで表す | × | BRIEF のデータ設計に合わせ、将来の「気になる」に備える |

### 検証方法
- 自動テスト：D1 に対して action を直接呼ぶ。2ユーザー分のデータで分離を確認する。
- 手動確認（Claude）：AC10。楽観的な表示の切り替えは、ブラウザで動かして確かめる。
