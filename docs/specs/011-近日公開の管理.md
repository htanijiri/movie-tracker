## 👤 ユーザーが確認するところ

### 何のための機能か
「劇場で見たい」にした公開前の映画が、いつ公開されるのかを、日付を読み解かなくても分かるようにする。

### できるようになること
- 「劇場で見たい」の映画のうち、公開前のものに、公開までの近さを言葉で出す。いまの「11月3日公開」の表示を置き換える。
  - 今日公開／明日公開
  - 今週公開（10/30）… 月曜から日曜までを1週間とする
  - 来週公開（11/3）
  - 今月公開（10/31）
  - 来月公開（11/20）
  - それより先は「12月25日公開」、年をまたぐ場合は「2027年1月8日公開」
  - 公開日が決まっていない映画は「公開日未定」（いまと同じ）
- 表示する場所：トップページとリストの「劇場で見たい」のカード、その映画の詳細画面（仕様書 010 と同じ）。

表示の例（今日が 2026/10/25（日）の場合）：
```
10/25 公開 → 今日公開
10/26 公開 → 明日公開            ← 月曜（来週）だが、「明日」を優先する
10/30 公開 → 来週公開（10/30）
11/10 公開 → 来月公開（11/10）
```

### やらないこと
- 公開日が近づいたときの通知（アプリの表示だけ）。
- 「劇場で見たい」以外の映画への表示。
- 公開前と公開中で、トップページの区分を分けること（並び順はいまのまま、公開日が早い順）。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [x] AC1：`releaseStatus` が、公開日と今日（日本時間）から、上の規則どおりの文言を返す。優先順位は 今日 → 明日 → 今週 → 来週 → 今月 → 来月 → それ以降（自動テスト：月末・年末・週の境目を含む表で確かめる）
- [x] AC2：週は月曜始まり。今日が日曜のとき、翌日（月曜）は「明日公開」になる（「明日」が「来週」より優先）（自動テスト）
- [x] AC3：カードと詳細画面に、仕様書 010 と同じ条件で表示される（自動テスト）

### 設計方針
- 仕様書 010 の `releaseStatus` に、公開前（`kind: "upcoming"`）の文言をまとめる。日付の計算は `YYYY-MM-DD` の文字列を UTC の日付として扱い、曜日は `getUTCDay()` で出す（タイムゾーンのずれを避ける）。

### 検証方法
- 自動テスト：表形式で、今日と公開日の組み合わせごとに期待する文言を確かめる。
