# 003 映画詳細

- 状態：完了
- 依存：002

## 👤 ユーザーが確認するところ

### 何のための機能か
見つけた映画が目当ての作品かどうかを確かめ、劇場で見るか、配信を待つか、見送るかを判断するための画面。

### できるようになること
- 映画ごとの詳細画面で、次の情報を見られる。
  - ポスター、日本語タイトル、原題、公開日、上映時間、ジャンル、あらすじ
  - 監督と主な出演者
  - 予告動画（押すと、その場で YouTube の動画が再生される）
  - 日本での配信状況（定額で見られるサービス、レンタル・購入できるサービス）。まだ配信がなければ「日本での配信情報はまだありません」と表示する
- 同じ画面の下に、自分の記録（見たい・きっかけ・見た記録。仕様書 004〜006）が並ぶ。

### データの扱い
- 映画の情報は TMDb から取得する。配信状況は TMDb 経由の JustWatch 提供のデータで、「JustWatch 提供」と表示する。実際の配信状況とずれていることがある。
- 予告動画は、再生ボタンを押したときに初めて YouTube につながる（押すまでは YouTube に何も送られない）。
- 日本語のあらすじや予告が TMDb に登録されていない作品では、その部分が空になるか、英語の予告が表示される。

### 使い方の流れ
1. 「探す」やトップページ、一覧から映画を押す。
2. 詳細画面で内容・予告・配信状況を確認する。

### やらないこと
- 配信が始まったことの検出と通知（Phase 2）。今回は、画面を開いた時点の配信状況を表示するだけ。
- 他の利用者のレビューや点数の表示。
- 出演者・監督から別の作品をたどる機能。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [x] AC1：`/movies/:tmdbId` の loader が、TMDb の `/3/movie/{id}` を `language=ja-JP`、`append_to_response=videos,watch/providers,credits`、`include_video_language=ja,en,null` で1回だけ呼ぶ（自動テスト）
- [x] AC2：HTML に、タイトル、原題、公開日（`YYYY/MM/DD` 形式）、上映時間、ジャンル、あらすじ、監督、出演者（先頭5人まで）が含まれる（自動テスト）
- [x] AC3：予告は、YouTube の `Trailer` を日本語 → 英語の順、同じ言語の中では公式（`official`）を優先して1本選ぶ。該当がなければ `Teaser`。どちらもなければ予告の欄を出さない（自動テスト）
- [x] AC4：初期表示の HTML に `youtube` を含む `iframe` がなく、再生ボタンを押した後にだけ `youtube-nocookie.com/embed/<key>` の iframe が挿入される（自動テスト：コンポーネントのテスト）
- [x] AC5：配信状況は `watch/providers` の `JP` だけを使い、`flatrate` を「定額で見られる」、`rent` と `buy` を「レンタル・購入」、`free` と `ads` を「無料」として、サービス名とロゴを表示する。TMDb が返す配信ページへのリンクと「JustWatch 提供」の表記を付ける（自動テスト）
- [x] AC6：`JP` の配信情報がないとき「日本での配信情報はまだありません」と表示する（自動テスト）
- [x] AC7：存在しない ID（TMDb が 404）では、404 のページ「映画が見つかりませんでした」を表示する。数字でない ID は TMDb を呼ばずに 404（自動テスト）
- [x] AC8：詳細を開いたとき、`movies` テーブルのスナップショット（タイトル、原題、公開日、ポスター）を upsert する（自動テスト）
- [x] AC9：あらすじ・ポスター・予告が欠けている作品でも、エラーにならず、欠けた部分だけが省かれる（自動テスト）
- [x] AC10：実際の TMDb のデータで、公開済みの有名な作品の詳細が日本語で表示され、配信状況が出る（手動：Claude）
- [ ] AC11：スマホで予告を再生できる（手動：ユーザー）

### 設計方針
- **取得**：`getMovieDetail(tmdbId)` が `append_to_response` で1回にまとめて取得し、画面用の型（`MovieDetail`）に変換する。Cache API で6時間キャッシュ。
- **スナップショット**：`movies` への upsert は loader の中で行う（一覧画面で TMDb を呼ばずにタイトルとポスターを出すため）。
- **予告**：ポスター風のサムネイル（`i.ytimg.com` の画像は使わず、TMDb の背景画像を使う）に再生ボタンを重ね、押したら iframe に差し替える。押すまで YouTube への通信を発生させない。
- **日付の表示**：公開日は TMDb の日本向けの日付をそのまま `YYYY/MM/DD` で表示。未定は「公開日未定」。
- **画面構成**：上から、背景画像＋ポスター＋タイトル → 自分の記録（004〜006 が差し込む領域）→ 予告 → あらすじ → 配信状況 → スタッフ・キャスト。登録の操作を最初の画面内に収めるため、自分の記録を上に置く。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| YouTube を押してから読み込む | ○ | 開いただけで外部に通信しない。表示も速い |
| YouTube の iframe を最初から埋め込む | × | 詳細を開くたびに YouTube に通信が発生する |
| YouTube へのリンクだけ | × | アプリから離れてしまい、登録の操作に戻りにくい |
| 配信状況を D1 に保存して差分を検出 | × | Phase 2 の範囲 |

### 検証方法
- 自動テスト：TMDb のレスポンスをフィクスチャでモック（全項目あり／欠損あり／JP の配信なし／404）。
- 手動確認（Claude）：AC10。実データでの見え方（画像の比率、長いあらすじ）を確認する。

### 実装中に変えたこと（2026-10-08）
- **公開日は、日本の劇場公開日を優先する（AC1 の `append_to_response` に `release_dates` を追加）。** `/movie/{id}` の `release_date` は世界で最初の公開日で、海外で先に公開された作品では日本の公開日とずれていた（トップページの「◯月◯日公開」と並び順に影響する）。日本の劇場公開日（種類 3、なければ 2）のうち最初の日付を使い、なければ従来の日付を使う。
- **AC4 の「再生ボタンを押した後」は、部品に初期状態を渡して確かめる形にした。** テストは Workers のランタイムの中で動かしており、クリックを再現する DOM がないため。実際に押したときの動き（押すまで YouTube への通信が0件、押すと iframe が入る）は、ブラウザで確認した。
- TMDb が応答できないときは、503 と「映画情報を取得できませんでした。時間をおいて試してください」を返す（受け入れ条件になかった場合の扱いを決めた）。
- キャッシュは入れなかった（理由は仕様書 000）。配信状況は、開くたびに最新を取得する。
- AC11（スマホでの予告の再生）は、ユーザーの手動確認として残る。
