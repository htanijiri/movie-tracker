# 012 映画のおすすめ

- 状態：ドラフト
- 依存：009（配信状況）、011

## 👤 ユーザーが確認するところ

### 何のための機能か
「今劇場でやっている映画でおすすめは？」「今配信されている邦画で好みに合うものは？」に答える。これまでの記録（★、見たい、見送り）から好みを計算して、作品を並べる。

### できるようになること
- **「探す」画面に「おすすめ」のタブを足す**（検索／公開中／近日公開／おすすめ）。
- おすすめの中で、2つを切り替えられる。
  - **劇場で公開中**：日本で公開中の映画から
  - **配信中**：日本で見放題（定額）か無料で見られる映画から（すべてのサービスが対象）
- さらに **すべて／邦画／洋画** で絞り込める。
- **好みに合いそうな順に20本**を、ポスター付きで並べる。各作品に、おすすめの理由を1行で出す。
  - 例：`★5の「映画A」と同じ「SF」`、`「映画B」（★4）の関連作品`
- 好みの計算に使う記録：
  - 見た映画の★（★5・★4は好き、★2・★1は苦手として扱う）
  - 「劇場で見たい」「サブスクで見たい」の映画（好きの方向に少し）
  - 「見送る」にした映画（苦手の方向に少し）
- すでにリストに入っている映画（見たい・見た・見送り）は、おすすめに出さない。
- 記録がまだ少ないうち（好みの手がかりが3本未満）は、人気の高い順に並べ、「記録が増えると好みに合わせて並びます」と表示する。

### データの扱い
- 映画の情報は TMDb から取得する。好みの計算はこのアプリの中で行い、記録（★や感想）を外部に送らない。
- 費用はかからない。

### 使い方の流れ
1. 「探す」→「おすすめ」を開く。
2. 「劇場で公開中」か「配信中」を選び、必要なら「邦画」などで絞る。
3. 気になった映画を押して詳細を開き、いつもどおり登録する。

### やらないこと
- 自由な文章での質問（AI は使わない）。
- 契約しているサービスでの絞り込み（すべてのサービスが対象）。
- 近日公開の映画のおすすめ。
- おすすめに出た映画を「興味なし」にして消す機能（「見送る」で登録すれば、次から出なくなる）。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| TMDb のデータで計算する（AI は使わない） | 無料で、記録を外部に送らない |
| 配信中は、日本のすべてのサービスを対象にする | ユーザーの指定（仕様書 009 と同じ） |
| 「探す」のタブに追加する | 映画を探す場所が1か所にまとまる。下のメニューは変えない |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの：
  - 公開版の「探す」→「おすすめ」で、並んだ作品と理由が、自分の好みに照らして納得できる（好みに合っているかは、本人にしか判断できないため）。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [ ] AC1：`/search?tab=recommend` に「おすすめ」のタブが出る。`source=theater|streaming`（既定は theater）と `lang=all|ja|foreign`（既定は all）を受け付け、不正な値は既定値として扱う（自動テスト）
- [ ] AC2：候補は、theater なら `/movie/now_playing`（`region=JP`）の1〜3ページ、streaming なら `/discover/movie`（`watch_region=JP`、`with_watch_monetization_types=flatrate|free|ads`、`vote_count.gte=30`、`sort_by=popularity.desc`）の1〜3ページ。`lang=ja` は `with_original_language=ja`（streaming）または取得後の絞り込み（theater）、`lang=foreign` は取得後に `original_language !== "ja"` で絞る（自動テスト）
- [ ] AC3：好みの重み：見た映画は ★5=+2、★4=+1、★3=0、★2=−1、★1=−2、★なし=+0.5。見たい（劇場・サブスク）=+1、見送り=−1。映画のジャンルごとに足し合わせ、候補のジャンルの重みの合計で並べる（自動テスト：架空の記録と候補で順位を確かめる）
- [ ] AC4：★4以上の見た映画のうち★の高い順に最大3本について `/movie/{id}/recommendations` を取得し、候補に含まれていれば加点し、理由を「「映画B」（★4）の関連作品」にする（自動テスト）
- [ ] AC5：理由の文言は、加点がいちばん大きかった根拠から作る（関連作品 → 同じジャンルの★の高い映画の順）。根拠がなければ理由を出さない（自動テスト）
- [ ] AC6：自分のリストにある映画（どの状態でも）は結果に含めない。他の利用者のリストは影響しない（自動テスト）
- [ ] AC7：手がかり（重みが0でない記録のうち、ジャンルが分かるもの）が3本未満なら、人気順に並べ、案内の文言を出す（自動テスト）
- [ ] AC8：結果は最大20本。1回の表示で TMDb を呼ぶのは10回以内（候補3＋関連作品3＋ジャンルの補完4）（自動テスト）
- [ ] AC9：TMDb が応答しないときは、「映画情報を取得できませんでした。時間をおいて試してください」を出し、500 にならない（自動テスト）
- [ ] AC10：実際の TMDb のデータで、両方の切り替えと絞り込みが動き、理由が出る。幅 375px で崩れない（手動：Claude）
- [ ] AC11：並んだ作品と理由が、好みに照らして納得できる（手動：ユーザー）

### 設計方針
- **ジャンルの情報**：自分の記録の映画のジャンルが必要なので、`movies` に `genre_ids`（JSON の数値の配列、NULL 可）を足す（マイグレーション。列の追加だけなので、古いコードが動いている間に適用しても壊れない）。詳細を開いたとき・スナップショットの取り直しのとき・仕様書 009 の定期実行のときに埋める。おすすめの表示のときにジャンルが分からない記録があれば、1回につき4本まで TMDb の詳細から補う。
- **計算**：`app/lib/recommend.server.ts`。`buildTasteProfile(records)` → `Map<genreId, weight>`、`scoreCandidates(candidates, profile, related)` → 並べ替えと理由。純粋な関数にしてテストしやすくする。ジャンル名は TMDb の `/genre/movie/list`（`language=ja-JP`）を使わず、候補・詳細に含まれる名前と、固定の対応表（TMDb のジャンル ID は固定）で出す。
- **点数**：ジャンルの重みの合計を、候補のジャンル数の平方根で割る（ジャンルが多い作品が有利になりすぎないため）。関連作品は +2（複数の根拠があれば足す）。最後に、人気（`popularity`）の順位で小さく加点して同点を崩す。
- **画面**：`/search` の loader に `tab=recommend` を足す。結果は「探す」と同じポスターのグリッドで、タイトルの下に理由を出す。「もっと見る」は出さない。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| TMDb のジャンルと関連作品から計算する | ○ | チャットで決定。無料で、記録を外部に送らない |
| AI（Claude）に聞く | × | ユーザーが選ばなかった（費用と、感想が外部に送られる） |
| TMDb の `/movie/{id}/recommendations` だけを並べる | × | 公開中・配信中に絞れない。★の低い映画の好みを反映できない |
| 監督・出演者も好みに使う | × | 候補ごとに詳細を取得する必要があり、1回の表示での TMDb の呼び出しが増えすぎる |

### 検証方法
- 自動テスト：架空の記録・候補・関連作品で、点数と順位、理由、除外、少ないときの扱いを確かめる。loader は TMDb をモックして確かめる。
- 手動確認（Claude）：AC10。
- 手動確認（ユーザー）：AC11。好みに合っているかは本人にしか判断できないため。
