# 009 配信開始チェック

- 状態：完了
- 依存：007、008

## 👤 ユーザーが確認するところ

### 何のための機能か
「サブスクで見たい」にした映画や、劇場で見逃した映画が、配信で見られるようになったことに気づけるようにする。いまは、映画の詳細を開かないと配信状況が分からない。

### できるようになること
- **毎日、自動で配信状況を確かめる。** 対象は「サブスク待ち」と「劇場で見たい」の映画。TMDb で日本の配信状況を調べる（1本につき1日1回）。
- **配信が始まったら、トップページのいちばん上に知らせる。**
  - 例：`🎉 「映画A」が Netflix で配信を始めました（10/24 確認）`
  - 押すと映画の詳細に進む。「確認した」を押すと、そのお知らせは消える。
  - その映画を視聴済み・見送りにしたり、リストから消したりしたときも消える。
- **カードにも、いま配信中かどうかを出す。** 「サブスク待ち」「劇場で見たい」のカードに、`📺 配信中：Netflix、U-NEXT` のように表示する（配信がなければ何も出さない）。
- 「配信が始まった」とみなすのは、**見放題（定額）か無料（広告付きを含む）で見られるサービスが、前回の確認より増えたとき**。日本のすべてのサービスが対象。
- 最初の確認のときにすでに配信されていた映画は、お知らせは出さず、カードに「配信中」とだけ出す（いつ始まったかは分からないため）。

### データの扱い
- 配信状況は TMDb（JustWatch 提供のデータ）から取得する。新しい外部サービスは使わない。
- 費用はかからない（Cloudflare の無料プランの、定期実行の機能を使う）。

### 使い方の流れ
1. ふだんどおり「サブスクで見たい」「劇場で見たい」で映画を登録しておく。
2. 配信が始まると、アプリを開いたときにトップページの上にお知らせが出る。
3. お知らせを押して詳細を確かめ、「確認した」で消す。

### やらないこと
- メールやスマホへの通知（アプリを開いたときに分かる形だけ）。
- 契約しているサービスの設定（すべてのサービスを対象にする）。
- レンタル・購入が始まったことの通知、配信が終わったことの通知。
- 視聴済み・見送りの映画の確認。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 対象は「サブスク待ち」と「劇場で見たい」の映画 | 劇場で見逃した映画が配信されたときにも気づける（計画書の「劇場で見逃した作品が配信されたことを知りたい」） |
| 日本のすべての配信サービスを対象にする（契約中のサービスの設定は作らない） | ユーザーの指定 |
| 知らせるのはアプリの中だけ | 外部のサービスも、ドメインのメールの設定の変更も要らない |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの：
  - 公開版のトップページで、すでに配信されている「サブスク待ち」の映画のカードに「📺 配信中：…」が出ている（ログインが必要な本番の画面は、Claude が開けないため）。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [x] AC1：定期実行の処理（`runStreamingCheck`）が、「サブスク待ち」「劇場で見たい」の映画だけを対象に、TMDb の `/3/movie/{id}/watch/providers` を呼ぶ。視聴済み・見送りの映画は呼ばない（自動テスト）
- [x] AC2：1回の実行で TMDb を呼ぶのは最大30本。前回の確認が古い順に選び、20時間以内に確認した映画は飛ばす（自動テスト）
- [x] AC3：初めて確認した映画では、お知らせを作らず、配信状況だけを保存する（自動テスト）
- [x] AC4：前回の確認より、`JP` の `flatrate`・`free`・`ads` のサービスが増えたとき、そのサービスごとに、その映画を対象の状態で登録している利用者全員にお知らせを作る。`rent`・`buy` だけが増えた場合は作らない。サービスが減っただけの場合も作らない（自動テスト）
- [x] AC5：同じ映画・同じサービスのお知らせは、利用者ごとに1つだけ（配信が一度終わって再開しても、未確認のものがあれば増やさない）（自動テスト）
- [x] AC6：TMDb が応答しない映画があっても、ほかの映画の確認は続ける。404 の映画は確認済みとして扱う（自動テスト）
- [x] AC7：トップページの loader が、確認していないお知らせを新しい順に返す。視聴済み・見送り・リストから消した映画のお知らせは返さない。他の利用者のお知らせは返さない（自動テスト）
- [x] AC8：`intent=dismiss-notice` の POST で、そのお知らせが消える。他の利用者のお知らせは消せない（自動テスト）
- [x] AC9：「サブスク待ち」「劇場で見たい」のカードに、保存済みの配信状況から `📺 配信中：…`（定額・無料のサービス名を最大3つ、超えたら「ほか」）が出る。配信がなければ出ない。視聴済み・見送りのカードには出ない（自動テスト）
- [x] AC10：`wrangler.jsonc` に定期実行（`triggers.crons`）が設定され、デプロイの出力に表示される（コマンド：CI のログ）
- [x] AC11：開発サーバーで定期実行を手動で呼び出し、実際の TMDb のデータで配信状況が保存され、カードに「配信中」が出る（手動：Claude）
- [x] AC12：本番のトップページで、配信中の「サブスク待ち」の映画に「配信中」が出る（手動：ユーザー。2026-10-25 に確認 OK）

### 設計方針
- **データ**（マイグレーションを1つ追加。既存の列は変えない）：
  - `movie_providers`：`tmdb_id`（PK、`movies` を参照）、`providers`（JSON。`[{id, name, logoPath, type}]`、type は `flatrate`／`free`。`ads` は `free` にまとめる）、`checked_at`。TMDb のデータなので、確認の対象から外れて30日を超えたものは `refreshStaleSnapshots` で消す。
  - `streaming_notices`：`id`、`user_id`、`tmdb_id`、`provider_id`、`provider_name`、`detected_at`、`dismissed_at`。`UNIQUE(user_id, tmdb_id, provider_id)`。
- **定期実行**：`workers/app.ts` に `scheduled` を足す。`crons: ["0 */4 * * *"]`（4時間ごと）。無料プランの1回あたりの外部への通信は50回までなので、1回に30本までにし、4時間ごとに回して1日180本まで確認できるようにする。各映画は20時間に1回まで。
- **TMDb**：`getWatchProviders(tmdbId)` を `client.server.ts` に足す（`/movie/{id}/watch/providers`）。詳細画面は、これまでどおり開いたときの最新を表示し、`movie_providers` は書き換えない（書き換えると、定期実行での差分が取れなくなるため）。
- **お知らせ**：トップページの loader で、未確認かつ対象の状態の映画のものを `movies` と結合して返す。トップページに action を足し、`intent=dismiss-notice` で `dismissed_at` を入れる。お知らせの表示は `NoticeList` コンポーネント。
- **カード**：一覧のクエリで `movie_providers` を左結合し、`ListItem` に `streamingProviders` を足す。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| Cloudflare の定期実行（Cron Triggers）で確かめる | ○ | 無料プランで使え、アプリと同じ場所で動く |
| トップページを開いたときに確かめる | × | 開くたびに登録本数ぶん TMDb を呼ぶことになり、表示が遅くなる |
| 詳細を開いたときにも保存済みの配信状況を更新する | × | 定期実行で「増えた」ことを検出できなくなる |
| 配信の開始を、配信状況の全件の比較ではなく「flatrate が空から空でなくなった」で判定する | × | 2つ目のサービスで始まったことに気づけない |

### 検証方法
- 自動テスト：TMDb の応答をモックし、`runStreamingCheck` を直接呼ぶ。トップページの loader・action・描画を確かめる。
- コマンド：CI のデプロイのログに、定期実行の設定が出ること。
- 手動確認（Claude）：AC11。開発サーバーで定期実行を呼び出す（`/cdn-cgi/handler/scheduled`）。
- 手動確認（ユーザー）：AC12。本番の画面はログインが必要で、Claude には開けないため。
