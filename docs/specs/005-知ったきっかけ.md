# 005 知ったきっかけの記録

- 状態：完了

## 👤 ユーザーが確認するところ

### 何のための機能か
「この映画をどこで知って、なぜ気になったのか」を残す。あとでリストを見返したときに、登録した理由を思い出せるようにする。

### できるようになること
- 登録済みの映画の詳細画面で、きっかけを記録できる。すべて任意で、書かなくても登録はできる。
  - 種類：映画館の予告／CM／Web広告／SNS／記事／人から聞いた／その他
  - 日付（入力を始めたとき、今日の日付が入っている）
  - 場所（例：映画館の名前。以前に入力した場所が候補に出る）
  - メモ（例：「映画A」の上映前）
- あとから書き足したり、直したり、消したりできる。
- 記録したきっかけは、トップページや一覧で、映画の下に1行で表示される（例：`2026/01/10 映画館の予告 ・ 「映画A」の上映前`）。

### 使い方の流れ
1. 映画を登録する（仕様書 004）。
2. 詳細画面の「きっかけ」の欄で種類を選ぶ。必要なら日付・場所・メモを入れて保存する。

### やらないこと
- 映画館に行った記録を独立して持つこと、「気になった予告が何本あったか」の記録（Phase 3）。
- 1本の映画に複数のきっかけを残すこと。
- きっかけの種類を自分で増やすこと。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [x] AC1：登録済みの映画に `intent=save-discovery` で種類・日付・場所・メモを POST すると、`discovery_type`・`discovery_date`・`discovery_place`・`discovery_note` が保存され、`status` と `preferred_medium` は変わらない（自動テスト）
- [x] AC2：種類は `THEATER_TRAILER`／`TV_CM`／`WEB_CM`／`SNS`／`ARTICLE`／`FRIEND`／`OTHER` の7つだけを受け付け、それ以外は 400（自動テスト）
- [x] AC3：日付は `YYYY-MM-DD` の実在する日付だけを受け付ける。空は NULL として保存する。場所は100文字、メモは500文字を超えると 400 で、入力内容を保ったままエラーを表示する（自動テスト）
- [x] AC4：すべての項目を空にして保存すると、4つの列が NULL になる（＝きっかけを消せる）（自動テスト）
- [x] AC5：未登録の映画への `save-discovery` は 400（自動テスト）
- [x] AC6：場所の候補として、その利用者が過去に入力した `discovery_place` と `watched_place`（視聴方法が劇場のもの）が、重複なしで新しい順に最大10件出る。他の利用者の入力は出ない（自動テスト）
- [x] AC7：1行表示の整形関数が、`日付 種類 ・ メモ` の形で返す。メモがなければ場所、どちらもなければ日付と種類だけ。すべて空なら空文字（自動テスト）
- [x] AC8：保存した HTML で、メモに入れた `<script>` がタグとして出力されない（自動テスト）
- [x] AC9：ブラウザで、きっかけを入力・保存・再編集できる（手動：Claude）

### 設計方針
- **action**：004 と同じ `/movies/:tmdbId` の action に `intent=save-discovery` を足す。
- **画面**：詳細画面の「自分の記録」の中に、折りたたみ（`<details>`）で置く。未入力のときは「きっかけを書く」、入力済みのときは1行表示と「編集」。種類は7つのチップ（ラジオボタン）、場所は `<input list>` ＋ `<datalist>`。
- **日付の初期値**：未入力でフォームを開いたときだけ、今日（`Asia/Tokyo`）を入れる。サーバー側で計算して渡す（Workers は UTC で動くため、タイムゾーンを明示する）。
- **整形**：`formatDiscovery(userMovie)` を `app/lib/format.ts` に置き、007 のカードでも使う。種類の日本語ラベルは定数表で持つ。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 映画の記録の中にきっかけを持つ | ○ | BRIEF のデータ設計どおり。Phase 1 では1映画1きっかけで足りる |
| 映画館に行った記録を別に持ち、そこからきっかけを関連付ける | × | Phase 3 の範囲 |
| 登録と同時にきっかけの入力を求める | × | 「詳細メモは後から書けばよい」という BRIEF の方針 |

### 検証方法
- 自動テスト：action と整形関数、候補のクエリを D1 に対してテストする。
- 手動確認（Claude）：AC9。折りたたみと候補表示の動きはブラウザで確かめる。
