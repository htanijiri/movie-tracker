# 008 「見た」の選択表示と、一覧での視聴方法の表示

- 状態：ドラフト
- 依存：006、007

## 👤 ユーザーが確認するところ

### 何のための機能か
実際に使ってみて分かった、2つの分かりにくさを直す。
- 映画詳細で「見た」を押しても、先に選んでいた「劇場で見たい」などが選ばれた見た目のまま残り、切り替わったように見えない。
- 一覧の視聴済みの映画で、どこで見たのか（劇場か、配信か）がひと目で分からない。

### できるようになること
- **「見た」を押すと、「見た」が選ばれた見た目になり、「劇場で見たい」「サブスクで見たい」「見送る」の強調は外れる。**
  - 記録されるタイミングは、いままでと同じ（入力欄の「保存」を押したとき）。
  - 「見た」をもう一度押して入力欄を閉じると、元の見た目（先に選んでいたボタンが強調された状態）に戻る。
  - 入力欄を開いたまま3つのボタンのどれかを押すと、そのボタンの内容で登録され、入力欄は閉じる。
- **視聴済みの映画のカードに、「✅ 視聴済み」のすぐ右に、どこで見たかのラベルが並ぶ。**
  - 🎬 劇場 ／ 📺 サブスク ／ 💿 レンタル・購入 ／ 📍 その他
  - リストの「視聴済み」「すべて」と、トップページの「最近見た」のどれでも、同じように表示される。
  - その下の行は、見た日と、入力していれば場所・サービス名（例：`2026/01/10 ・ 映画館X`）、評価の★。

表示の例：
```
映画A
[✅ 視聴済み] [🎬 劇場]
2026/01/10 ・ 映画館X  ★★★★☆

映画B
[✅ 視聴済み] [📺 サブスク]
2026/01/08 ・ 配信サービスA
```

### 使い方の流れ
1. 映画詳細で「見た」を押す。「見た」が選ばれた見た目になる。
2. 見た日や視聴方法を確かめて「保存」を押す。
3. リストやトップページで、その映画に「どこで見たか」のラベルが付いている。

### やらないこと
- 「見た」を押した瞬間に記録すること（見た日や視聴方法を確かめてから記録する形のままにする）。
- 入力欄の中への説明文の追加。
- 画面の構成の変更。
- 視聴方法での絞り込みや並べ替え。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 「見た」を押したら、見た目だけを切り替える。入力欄への説明の表示は付けない | ユーザーの指定 |
| 「どこで見たか」は、視聴済みのカードすべてに出す | 画面によって表示が違う、ということが起きない |
| 「どこで見たか」は、アイコンと文字のラベルで出す | アイコンの意味を覚えていなくても分かる |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの：
  - スマホの実機で、「見た」を押したときの見た目の切り替わりが分かりやすい（分かりやすさは、機械では判定できないため）。

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [ ] AC1：「見た」の入力欄が開いている状態では、3つのボタンのどれにも `aria-pressed="true"` が付かない。閉じている状態では、登録済みの区分のボタンにだけ付く（自動テスト：入力欄の開閉の初期状態を渡して描画する）
- [ ] AC2：「見た」の入力欄が開いている状態では、「見た」の見出し（`summary`）に、選択中を示す属性（`data-selected="true"`）と強調のクラスが付く。閉じている状態では付かない（自動テスト）
- [ ] AC3：入力欄の開閉だけでは、サーバーへの送信が発生しない（自動テスト：開いた状態で描画しても、DB の行が変わらないこと。開閉は画面の状態だけで持つ）
- [ ] AC4：入力エラーで戻ってきたとき（入力欄が開いた状態で表示される）も、AC1・AC2 の見た目になる（自動テスト）
- [ ] AC5：視聴済みのカードに、`data-watched-medium` を持つラベルが出る。文言は `THEATER`→「🎬 劇場」、`STREAMING`→「📺 サブスク」、`RENTAL`→「💿 レンタル・購入」、`OTHER`→「📍 その他」（自動テスト）
- [ ] AC6：視聴済みでないカード（劇場で見たい、サブスク待ち、見送り）には、このラベルが出ない（自動テスト）
- [ ] AC7：視聴済みのカードの下の行は「見た日 ・ 場所」。場所が未入力なら見た日だけ（視聴方法の文言を重ねて出さない）（自動テスト）
- [ ] AC8：トップページの「最近見た」と、リストの「視聴済み」「すべて」の3か所で、同じラベルが出る（自動テスト）
- [ ] AC9：ブラウザ（幅 375px）で、「見た」を押す → 強調が切り替わる → もう一度押す → 元に戻る → 開いたまま別のボタンを押す → 登録されて入力欄が閉じる、を操作して確かめる。カードのラベルが折り返しても崩れず、横スクロールが出ない（手動：Claude）
- [ ] AC10：実機のスマホで、切り替わりが分かりやすい（手動：ユーザー）

### 設計方針
- **入力欄の開閉の状態**：`MyRecord` に `watchedOpen` を持ち、`WatchedForm` の `<details>` を制御する（`open` と `onToggle`）。初期値は、入力エラーがあるとき true。`MediumButtons` には `suppressed`（＝`watchedOpen`）を渡し、true の間は選択中のボタンを強調しない。3つのボタンの `onClick` で `watchedOpen` を false にする（同じ区分を押し直した場合も閉じるため）。
- **状態は画面だけで持つ**：開閉でサーバーに送信しない。JavaScript が動かない場合、3つのボタンの強調は外れない（開閉は `<details>` として動く）。「見た」自身の強調は、CSS（`details[open] > summary`）でも付くようにする。
- **カードのラベル**：`app/lib/labels.ts` に `WATCHED_MEDIUM_BADGES`（絵文字と短い文言）を足す。詳細画面の「視聴方法」の文言（`WATCHED_MEDIUM_LABELS`。「サブスク配信」など）は変えない。`MovieCard` の `watchedLine` から、視聴方法の文言へのフォールバックを外す。
- **仕様書 006・007 との関係**：006 の「使い方の流れ」と 007 の AC5（場所がなければ視聴方法を出す）を、この仕様書が上書きする。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 見た目だけを切り替える（記録は「保存」のとき） | ○ | チャットで決定 |
| 「見た」を押した瞬間に記録する | × | ユーザーが選ばなかった。後日まとめて記録するとき、日付を直し忘れると間違った日付が残る |
| CSS の `:has()` だけで3つのボタンの強調を外す | × | 見た目は変えられるが、`aria-pressed` が true のまま残り、読み上げと見た目が食い違う |
| ラベルをアイコンだけにする | × | チャットで決定（アイコンと文字） |

### 検証方法
- 自動テスト：`MyRecord` に、入力欄を開いた状態で描画するためのテスト用の初期値を渡し、HTML を確かめる。カードは、4つの視聴方法と、視聴済みでない状態のデータで確かめる。
- 手動確認（Claude）：AC9。押したときの切り替わり（状態の変化）は、クリックを再現できる DOM がテスト環境にないため、ブラウザで確かめる。
