# 001 ログイン（自分だけが使えるようにする）

- 状態：完了
- 依存：000

## 👤 ユーザーが確認するところ

### 何のための機能か
公開 URL を知っている他人が、勝手に映画を登録したり、記録を書き換えたりできないようにする。

### できるようになること
- Google アカウントでログインできる。パスワードをこのアプリに入力することはない。
- **あらかじめ許可したメールアドレスの Google アカウントだけ**が使える。それ以外のアカウントでログインしようとすると、「このアプリは現在、作者だけが利用できます」と表示され、何も見られない。
- ログインしていない人に見えるのは、ログイン画面とクレジットのページだけ。
- 一度ログインすると、その端末では30日間ログインしたままになる。メニューからログアウトできる。

### データの扱い
- Google から受け取るのは、メールアドレス、名前、Google 側の利用者番号の3つ。この3つをデータベースに保存する。
- こちらから Google に映画の記録などを送ることはない。
- 許可するメールアドレスは秘密情報として扱い、公開リポジトリには書かない。

### 使い方の流れ
1. 公開 URL を開くと、ログイン画面が出る。
2. 「Google でログイン」を押し、Google の画面でアカウントを選ぶ。
3. トップページが表示される。

### やらないこと
- 自分以外の人の利用登録（一般公開するときに作る。データは最初から利用者ごとに分けて保存するので、あとから対応できる）。
- GitHub ログイン、メールのリンクでのログイン。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| Google ログインにし、自分のアカウントだけを許可する | ユーザーの指定。一般公開にそのまま発展させやすい |

### ユーザーにお願いすること
- 実装前に準備するもの（先に済ませておくと、実装が途中で止まらない。未了でも、これに依存しない部分は先にすべて作る）：
  - Google Cloud の管理画面で、ログイン用の設定（OAuth クライアント。種類は「ウェブ アプリケーション」）を作る。「承認済みのリダイレクト URI」に次の2つを登録する。
    - `https://movie-tracker.tanijiri.dev/auth/google/callback`
    - `http://localhost:5183/auth/google/callback`
  - 発行された2つの値と、許可するメールアドレスを、設定ファイル（`.dev.vars`）に次の名前で書く（チャットには貼らない）：`GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`ALLOWED_EMAILS`。
- 完成後に手で確認するもの：
  - 公開 URL で、自分の Google アカウントでログインでき、トップページが表示される。
  - 別の Google アカウント（持っていれば）では「作者だけが利用できます」と表示される。
  - （理由：Claude は Google アカウントのパスワードを入力するログイン操作を行えないため）

- [x] AC2：`/auth/google` が、`client_id`・`redirect_uri`・`state`・`code_challenge`（S256）・`scope=openid email profile` を含む Google の認可 URL へリダイレクトし、`state` と `code_verifier` を HttpOnly の Cookie に保存する（自動テスト）
- [x] AC3：コールバックで `state` が Cookie と一致しない場合は 400 で、セッションを作らない（自動テスト）
- [x] AC4：トークン交換（モック）で得た ID トークンの `email` が `ALLOWED_EMAILS` に含まれ、`email_verified` が true のとき、`users` に行を作成（2回目以降は同じ行を再利用）し、セッション Cookie を発行して `/` へリダイレクトする（自動テスト）

- [x] AC7：セッション Cookie は `HttpOnly`、`SameSite=Lax`、`Max-Age=2592000`、本番では `Secure`。署名を改ざんした Cookie は未ログインとして扱う（自動テスト）

- [x] AC9：`Origin` ヘッダーが自サイトと異なる POST は 403（自動テスト）
- [x] AC10：開発用ログイン `/auth/dev-login` は開発サーバーでだけ動き、本番ビルドの成果物に `dev-login` の文字列が含まれない（コマンド：`pnpm build` 後に `grep -r dev-login build/` が0件）
- [ ] AC11：公開 URL で、自分のアカウントでログインできる。別アカウントでは拒否される（手動：ユーザー）

### 設計方針
- **フロー**：OAuth 2.0 認可コード ＋ PKCE。ライブラリは `arctic`（Google プロバイダ）。ID トークンは Google のトークンエンドポイントから TLS で直接受け取るので、署名検証は省略し、`iss`・`aud`・`exp`・`email_verified` のクレームを検証する。
- **セッション**：React Router の `createCookieSessionStorage`（`SESSION_SECRET` で署名）に `userId` だけを入れる。ステートレスにして、D1 への問い合わせを減らす。
- **認可**：`requireUser(request, context)` を全ルートの loader / action の先頭で呼ぶ共通関数にする。`/about`、`/login`、`/auth/*` だけ除外。`ALLOWED_EMAILS` はカンマ区切り、大文字小文字を無視して比較。
- **データの分離**：`user_movies` のすべてのクエリは `user_id` を条件に含める（クエリ関数の引数で `userId` を必須にする）。
- **CSRF**：`SameSite=Lax` に加え、GET 以外のリクエストで `Origin` を検証する処理をエントリに置く。
- **開発用ログイン**：`import.meta.env.DEV` のときだけルートを登録し、`ALLOWED_EMAILS` の先頭のメールアドレス（未設定なら `dev@example.com`）のユーザーでセッションを作る。Claude がブラウザで画面を確認するために使う。
- **リダイレクト URI**：`http://localhost:5183/auth/google/callback` と `https://movie-tracker.tanijiri.dev/auth/google/callback`。リクエストの origin から組み立てる。開発サーバーのポートは 5183 に固定する（Google に登録した URI と一致させるため。Vite の既定の 5173 は、ほかのプロジェクトの開発サーバーとぶつかったので使わない）。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| Google ログイン ＋ メールアドレスの許可リスト | ○ | チャットで決定 |
| 合言葉1つ | × | ユーザーが Google ログインを選択 |
| Cloudflare Access（Zero Trust）で入口を守る | × | アプリの外の設定になり、一般公開時に作り直しになる。利用者の識別をアプリ内で持てない |

### 実装中に変えたこと（2026-10-08）
- **ログインの確認は、レイアウトのミドルウェアで行う。** React Router v8 ではミドルウェアが正式な機能になっていたので、ログインが必要なルートをすべて `routes/app-layout.tsx` の下に置き、そのミドルウェアで確認する形にした（設計方針では「各ルートの loader / action の先頭で `requireUser`」）。loader / action でも `requireUser(context)` を呼び、レイアウトの外にルートを置いてしまった場合は 401 で止まるようにしている。ルートの構成そのものも、テスト（`test/routes/structure.test.ts`）で固定した。
- **セッションの Cookie には、利用者の ID・メールアドレス・名前を入れる**（設計方針では「`userId` だけ」）。リクエストのたびに「メールアドレスが今も許可リストにあるか」を確かめるためで、許可リストから外せば、発行済みのセッションもすぐに使えなくなる。
- **Origin の検証は二重になっている。** 画面のあるルートへの POST は、React Router 自身が Origin の不一致を 400 で拒否する。画面のないルート（`/logout`）は、自前のミドルウェアが 403 で拒否する。
- **開発用ログインのリンクは `import.meta.env.DEV &&` で直接囲む。** loader が返したフラグで出し分ける作りにしたら、本番のビルドに `dev-login` の文字列が残り、AC10 に引っかかった。
- 開発サーバーのポートを 5183 に固定した（理由は仕様書 000）。**手元用のリダイレクト URI は `http://localhost:5183/auth/google/callback` に変わった。**
- **本番での確認（2026-10-09）**：Google の設定値を本番に登録したあと、`/auth/google` が 302 で Google の認可 URL に送ること、`redirect_uri` が公開 URL のコールバックであること、照合用の Cookie に `HttpOnly`・`Secure`・`SameSite=Lax` が付くことを `curl` で確かめた。Google の認可エンドポイントは、本番用・手元用のどちらのリダイレクト URI でも、エラー（`redirect_uri_mismatch` など）を出さずにログイン画面を返した。実際にログインできること（AC11）は、ユーザーの手動確認として残る。
