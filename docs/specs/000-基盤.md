## 👤 ユーザーが確認するところ

### 何のための機能か
アプリを動かす土台。手元の Mac で動かして確かめられ、GitHub にソースを公開し、GitHub に送るだけで公開版が更新される状態を作る。

### できるようになること
- スマホと PC のブラウザから、公開 URL **`https://movie-tracker.tanijiri.dev`** でアプリを開ける。画面はスマホの幅を優先して作り、表示は日本語にする。
- 入口はこの URL の1つだけにする。Cloudflare が自動で用意する別の URL（`〜.workers.dev`）は無効にする。
- ソースコードが、GitHub の**公開リポジトリ** `movie-tracker` に MIT License で置かれる。
- GitHub に送る（main ブランチに push する）と、自動テストが走り、通ったときだけ公開版が更新される。データベースの構造の変更も同時に反映される。テストが失敗した場合、公開版は変わらない。
- クレジットのページがあり、TMDb のロゴと「This product uses the TMDB API but is not endorsed or certified by TMDB.」の表記、配信情報が JustWatch 提供であることを表示する。このページはログインしていなくても見られる。

### 使う外部サービスと費用
| サービス | 何に使うか | 費用 |
|---|---|---|
| Cloudflare（Workers / D1） | アプリを動かす場所と、登録したデータの保存先 | 無料プランの範囲。上限（1日10万アクセスなど）を超えた場合は、その日だけエラーになり、料金は発生しない |
| Cloudflare（ドメイン） | 取得済みの独自ドメインのサブドメインを、公開 URL に使う | 追加の費用なし（ドメイン自体の更新料は従来どおり） |
| GitHub | ソースコードの公開、自動テスト、自動デプロイ | 公開リポジトリは無料 |
| TMDb | 映画の情報（仕様書 002・003） | 無料（非商用の利用に限る） |
| Google | ログイン（仕様書 001） | 無料 |

### 公開されるもの・されないもの
- **公開される**：ソースコード、仕様書、ドキュメント（README、TASKS、docs/）、CLAUDE.md と `.claude/` の設定、コミットの履歴（Git に設定済みの名前とメールアドレスを含む）。公開 URL のドメイン名も、設定ファイルとドキュメントに書かれる。
- **公開されない**：計画書（brief/）、作業ジャーナル（journal/）、秘密情報を書いた設定ファイル、アプリに登録した映画のデータ。
- 仕様書やドキュメントには、人名・実際に行った場所や日付などの個人的な情報を書かない（例は架空のものにする）。

### 使い方の流れ
1. Claude がコードを変更して GitHub に送る。
2. 自動テストが通ると、数分で公開版が更新される。
3. スマホや PC で公開 URL を開いて使う。

### やらないこと
- 確認用の別環境（プレビュー環境）。公開版と手元の2つだけにする。
- 広告・課金などの商用利用（TMDb の無料利用の条件から外れるため）。
- TMDb から取得したデータや画像をリポジトリに含めること（MIT License の対象は自分のソースコードだけ、と README に明記する）。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 今回は公開して、スマホからも使えるようにする | 映画を見た帰りにスマホで登録したいため |
| デプロイ先は Cloudflare | ユーザーの指定 |
| 公開 URL は、Cloudflare で取得済みの独自ドメインを使い `movie-tracker.tanijiri.dev` にする（2026-10-08） | ユーザーの指定。ドメインが同じ Cloudflare のアカウントにあるので、設定はデプロイのときに自動で行われる |
| `〜.workers.dev` の URL は無効にする（Claude の判断） | 入口を1つにして、ログインの設定と確認する場所を減らす |
| データの保存先は Cloudflare D1 | アプリと同じアカウントで完結し、接続用のパスワードの管理が不要。無料枠で足り、休止もしない |
| フレームワークは React Router v7 | Cloudflare が公式に対応しており、手元でも本番と同じ仕組みで動く。TMDb のトークンをサーバー側に隠せる |
| GitHub には最初から公開で置く | ユーザーの指定（BRIEF でも公開を想定） |
| ライセンスは MIT License。著作権表示は GitHub のユーザー名 | BRIEF の想定どおり |
| GitHub に push すると自動で公開版を更新する | ユーザーの指定 |
| 自動更新の仕組みは GitHub Actions にする（Claude の判断） | Cloudflare 側の連携機能は、標準の権限ではデータベースの構造を更新できない。GitHub Actions なら、テストが通ったときだけ更新する流れも同じ場所に書ける |

- 実装前に準備するもの（先に済ませておくと、実装が途中で止まらない。未了でも、これに依存しない部分は先にすべて作る）：

  2. ターミナルで `npx wrangler login` を実行し、ブラウザで Cloudflare にログインする（独自ドメインを持っているアカウントで）。

- 実装がひととおり終わった時点で、手順を添えてお願いするもの（Claude が作る GitHub のリポジトリに依存するため、先にはできない）：

### 設計方針
- **構成**：React Router v7（framework mode、SSR）＋ `@cloudflare/vite-plugin` ＋ Cloudflare Workers。DB は D1、ORM は Drizzle（`drizzle-kit generate` で SQL マイグレーションを出力し、`wrangler d1 migrations apply` で適用）。スタイルは Tailwind CSS v4。パッケージ管理は pnpm。TypeScript は strict。
- **ひな形**：`pnpm create cloudflare@latest --framework=react-router` 相当を、既存のファイル（CLAUDE.md、docs/ など）を壊さないよう一時フォルダに生成してから取り込む。
- **ディレクトリ**：`app/routes/`（画面）、`app/lib/`（`db/` スキーマとクエリ、`tmdb/` クライアント、`auth/`）、`workers/app.ts`（エントリ）、`migrations/`、`test/`。
- **設定キー**（秘密情報。手元は `.dev.vars`、本番は Workers のシークレット。`.dev.vars.example` を必ず揃える）：`TMDB_ACCESS_TOKEN`、`GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`ALLOWED_EMAILS`、`SESSION_SECRET`。`wrangler.jsonc` には秘密情報を書かない（D1 の `database_id` は識別子であり秘密ではないので書いてよい）。
- **DB スキーマ**（このフェーズで3テーブルとも作る。各仕様書で列を足さない）：
  - `users`：`id`（UUID）、`google_sub`（UNIQUE）、`email`、`name`、`created_at`
  - `movies`（一覧表示用の最小限のスナップショット。TMDb の規約に合わせ、30日より古いものは次に参照したとき取り直す）：`tmdb_id`（PK）、`title`、`original_title`、`release_date`、`poster_path`、`fetched_at`
  - `user_movies`：`id`、`user_id`、`tmdb_id`、`status`（`INTERESTED`/`WANT_TO_WATCH`/`WATCHED`/`SKIPPED`）、`preferred_medium`（`THEATER`/`STREAMING`/`RENTAL`/`ANY`/`NONE`、NULL 可）、`discovery_type`、`discovery_date`、`discovery_place`、`discovery_note`、`watched_at`、`watched_medium`、`watched_place`、`rating`、`review`、`created_at`、`updated_at`。`UNIQUE(user_id, tmdb_id)`。値の種類は BRIEF の将来分も含めて CHECK 制約に入れておき、Phase 1 の画面では一部だけを使う。
- **公開 URL**：`wrangler.jsonc` に `routes: [{ "pattern": "movie-tracker.tanijiri.dev", "custom_domain": true }]`、`workers_dev: false`、`preview_urls: false`。ゾーンが同じアカウントにあるので、DNS レコードと証明書はデプロイ時に自動で作られる。同名の DNS レコードがすでにある場合は上書きせず、ユーザーに確認する。`.dev` は HTTPS 必須（HSTS preload）なので、HTTP の経路は考えない。
- **CI 用の API トークンの権限**：アカウントの Workers Scripts（編集）と D1（編集）に加え、カスタムドメインを含むデプロイに必要なゾーン側の権限（Workers Routes の編集など）。必要な最小の組み合わせは実装時に公式ドキュメントで確認し、DEPLOY.md に書く。
- **CI/CD**：`.github/workflows/deploy.yml`。`test` ジョブ（install → typecheck → lint → test → build）は push と pull_request で実行。`deploy` ジョブは `needs: test`、main への push のときだけ、`wrangler d1 migrations apply DB --remote` → `wrangler deploy`。シークレットは `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID`。トークンが未登録の間はデプロイのステップをスキップして失敗扱いにしない。
- **初回のセットアップ**（Claude が手元で実行。`wrangler login` 済みが前提）：`wrangler d1 create movie-tracker` → `database_id` を `wrangler.jsonc` に記入 → マイグレーション適用 → `wrangler deploy` → `wrangler secret bulk` で本番のシークレットを登録（値は表示しない）。
- **公開前の確認**：最初の push の前に、AC5 のコマンドと、ドキュメント内の個人的な情報（人名、実在の施設名と日付の組み合わせ）の有無を確認する。
- **クレジット**：`/about` に TMDb のロゴ（TMDb が配布している SVG。自分のブランド表示より目立たせない）と表記、JustWatch の表記、リポジトリへのリンク。フッターから全画面でリンクする。
- **docs の更新**：README（構成、セットアップ、デプロイ）、DEPLOY.md、CLAUDE.md（コマンド、デプロイ）、TECH_NOTES（アーキテクチャ）をこの仕様書の完了時に埋める。LICENSE（MIT）を追加する。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| React Router v7 ＋ Cloudflare Workers ＋ D1 | ○ | チャットで決定。開発サーバーが Workers のランタイムで動くので、手元と本番の差が小さい |
| Next.js ＋ OpenNext | × | Cloudflare では変換層を挟むためサイズが大きくなりやすく、無料プランの上限や手元との挙動の差でハマる可能性がある |
| Hono ＋ React（SPA） | × | 画面側のデータ取得と状態管理を自分で書く量が増える |
| Vercel ＋ Neon / Supabase | × | ユーザーが Cloudflare を指定 |
| Cloudflare Workers Builds（管理画面で GitHub と連携） | × | 自動生成されるトークンに D1 の権限がなく、マイグレーションをビルド内で適用できない。テスト成功を条件にする制御も GitHub Actions のほうが書きやすい |
| 手元のコマンドだけでデプロイ | × | ユーザーが push での自動更新を選択 |
| `〜.workers.dev` の URL で公開 | × | ユーザーが独自ドメインを指定。独自ドメインなら Cache API も確実に使える |
| 独自ドメインと `〜.workers.dev` の両方を有効にする | × | 入口が2つになり、OAuth のリダイレクト先や Cookie の確認が2倍になる |
| Prisma | × | Workers ＋ D1 では Drizzle のほうが軽く、SQL マイグレーションをそのまま `wrangler` で適用できる |

### 検証方法
- 自動テスト：Vitest ＋ `@cloudflare/vitest-pool-workers`（miniflare 上の実物の D1 にマイグレーションを適用してテストする）。外部 API（TMDb、Google）への通信はすべてモックし、秘密情報なしで全テストが通るようにする。
- コマンド：上記 AC のとおり。
- 手動確認（Claude）：AC11 は、開発用ログイン（仕様書 001）で入り、ブラウザのモバイル表示で各画面を開いて確認する。レイアウトのはみ出しは自動テストでは検出しにくいため。
