# 014 AI に相談して予告を探す

- 状態：実装中（残りは AC11：API キーの登録後の本番での確認、AC12：ユーザーの確認）
- 依存：013

## 👤 ユーザーが確認するところ

### 何のための機能か
仕様書 013 の「予告を探す」では、目当ての予告を見つけられなかった。候補を注目度の高い順に並べるだけで、覚えている手がかり（「アクションだった」「あの俳優が出ていた」など）で絞り込めないためだ。また、手がかりは見終わった直後でないとすぐに忘れてしまう。そこで、覚えていることを AI に伝え、AI が Web 検索をしながら候補を絞り込めるようにする。

### できるようになること
- **「予告を探す」画面に「AI に相談」を足す。**
  - 覚えていることを書いて送ると、AI（Claude Sonnet 5.5）が Web 検索で調べ、候補を出す。手がかりが足りないときは、AI から聞き返す。
  - 例：`洋画のアクションで、主人公がカーチェイスしていた。最後に「来春公開」と出た気がする`
  - AI が出した候補は、これまでと同じカード（`▶ 予告を見る`・`これだった 👍`・`違う`）で出る。AI がその候補を挙げた理由も一言添える。
  - 候補が違ったら、「違う」を押すか、続けて手がかりを書き足す。AI は「違う」にした作品を除いて考え直す。
  - 返答には、検索に時間がかかるため、30秒ほどかかることがある。
- **見終わった直後に相談できるようにする。** 「見た」の記録で視聴方法を「劇場」にして、「気になった予告」を1本以上にして保存したら、そのまま「予告を探す」画面に進む。
- **会話は、予告探しごとに保存する。** あとで開き直しても、続きから相談できる。
- これまでの候補一覧（見た日の前後に公開される映画を、注目度の高い順に並べたもの）は、「AI に相談」の下に残す。
- **使いすぎを防ぐ。** AI の返答は1日20回まで（日付は日本時間で数える）。画面に、今日あと何回使えるかを出す。

### 使い方の流れ
1. 映画館で見終わったら、アプリでその映画に「見た」を付ける。視聴方法「劇場」と、「気になった予告」の本数を選んで保存する。
2. そのまま「予告を探す」画面に進むので、「AI に相談」に覚えていることを書いて送る。
3. AI の候補の予告を見て、「これだった 👍」か「違う」を押す。見つからなければ、思い出したことを書き足す。
4. その場で終わらなくても、あとでトップページの「🎞 予告を探す」から続けられる。

### データの扱い
- **新しく使う外部サービス：Anthropic の API**（Claude を動かすサービス）。
- **AI に送るもの**は次の4つだけ。
  - 「AI に相談」に書いた内容（それまでの会話を含む）
  - 見た映画のタイトルと見た日
  - その時期に公開される映画の候補（タイトルと公開日）
  - 「違う」にした作品のタイトル
- **送らないもの**：映画館の名前、★や感想、ほかの記録、メールアドレス。
- Anthropic の API は、既定では送った内容を学習に使わない。
- AI は、Anthropic 側で Web 検索をする。このアプリがほかのサイトを読み込むこと（スクレイピング）はしない。候補の作品は、これまでどおり TMDb で特定する。
- 保存する会話は、自分が書いた内容と AI の返答の本文、候補の作品だけ。検索結果の記事の内容は保存しない。見た記録を取り消したとき・リストから消したときは、会話も消える。

### 費用
- 料金は、Sonnet 5.5 が100万トークンあたり入力 2ドル、出力 10ドル。Web 検索は1,000回あたり 10ドルで、検索結果も入力として数えられる。
- 見込みは、返答1回（検索は最大5回）でおよそ 0.1〜0.2ドル。1回の相談で数往復すると、0.5ドル前後（約75円）になる。
- 使いすぎの防止は2つ。
  - アプリの側：AI の返答は1日20回まで。
  - Anthropic の管理画面：月の上限額（例：5ドル）。ユーザー自身が設定する。

### やらないこと
- 音声や画像による予告の認識（映画館で録音・撮影はしない）。
- AI に、ほかの機能（おすすめ、配信開始チェックなど）を担当させること。
- AI の返答を、ほかの利用者と共有すること。
- 1日20回を超えて使えるようにする設定の画面。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 「予告を探す」画面に「AI に相談」を足す。AI は聞き返しながら絞り込み、候補はこれまでと同じカードで出す。これまでの候補一覧も残す | 覚えている手がかりで絞り込めるようにする。見つけたあとの操作は変えない |
| 「気になった予告」を1本以上にして保存したら、そのまま「予告を探す」画面に進む | 見終わった直後、忘れる前に相談できる |
| 会話は予告探しごとに保存し、あとから続けられる | 一度で見つからなくても、思い出したことを足していける |
| AI に送るのは、書いた内容・見た映画のタイトルと見た日・その時期の候補・「違う」にした作品だけ。映画館の名前、★や感想は送らない | 絞り込みに要るものだけを送る |
| AI は Claude Sonnet 5.5 で、Web 検索を使う | ユーザーの指定。使う回数が少ないので、性能を優先する |
| AI の返答は1日20回まで。月の上限額は Anthropic の管理画面で設定する | 使いすぎを防ぐ |
| 「映画の情報は TMDb の API だけから取る」の決まりを、「AI の Web 検索の結果も、絞り込みに使う」に広げる。アプリ自身はスクレイピングしない。作品の特定は TMDb で行う | Web 上の予告の記事などがないと、手がかりから作品を特定できない |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 実装が終わってから、まとめてお願いするもの：
  - Anthropic の API キーを作り、決まったコマンド1つで登録する（秘密情報なので、Claude は作ることも入力することもできないため）。
  - Anthropic の管理画面で、月の上限額を設定する（支払いに関わる設定のため）。
- 完成後に手で確認するもの：
  - 実際に映画館で見た映画で、「AI に相談」して目当ての予告を見つけられるか（AI の候補が役立つかは、本人にしか判断できないため）。

- [x] AC6：Anthropic の API がエラー・時間切れ・拒否（`stop_reason: refusal`）を返したときは、案内を出し 500 にならない。その回は残り回数を減らさず、会話にも残さない（自動テスト）

### 設計方針
- **依存**：`@anthropic-ai/sdk`（TypeScript の公式 SDK）。呼び出しは `app/lib/ai/trailer-chat.server.ts` に閉じ込める。
- **API の呼び方**：
  - `model: "claude-sonnet-5-5"`、`thinking: { type: "adaptive" }`、`max_tokens` は 4,000 程度。
  - ツールは Web 検索（`web_search_20260209`、`max_uses: 5`、`user_location` は日本）と、候補を返すためのクライアントツール `show_candidates`（`strict: true`、入力は `{ message, candidates: [{ tmdbId?, title, originalTitle?, year?, reason }] }`）。`tool_choice` は `auto`（Sonnet 5.5 では強制指定が 400 になる）。システムプロンプトで「最後に必ず `show_candidates` を呼ぶ」と指示する。`show_candidates` が呼ばれなかったときは、本文だけを返答として扱い、候補は0件にする。
  - `stop_reason: "pause_turn"` のときは、続きを最大2回まで要求する。
  - システムプロンプトと TMDb の候補の一覧は、会話の間で変わらない部分として先頭に置き、プロンプトキャッシュを効かせる。
- **会話の保存**：`trailer_chats`（`id`、`user_id`、`visit_tmdb_id`、`role`（`user`／`assistant`）、`content`（本文）、`candidates`（JSON：`[{ tmdbId, reason }]`、assistant だけ）、`created_at`）。2回目以降の送信では、保存した本文だけを会話として送る（検索結果のブロックは送り直さない。費用を抑え、記事の内容を保存しないため）。
- **1日の上限**：`trailer_chats` の `role = 'assistant'` の行を、日本時間の今日の範囲で数える。上限は定数 `DAILY_AI_REPLIES = 20`。
- **秘密情報**：`ANTHROPIC_API_KEY` を `SECRET_KEYS` に足す。`.dev.vars.example`、`vitest.config.ts` の `miniflare.bindings`（ダミー値）、docs/DEPLOY.md を揃える。
- **画面**：`/trailers/:tmdbId` の「見つけた予告」の下、これまでの候補一覧の上に「AI に相談」の欄を置く。送信は `useFetcher` で行い、送信中は「AI が調べています（30秒ほどかかることがあります）」を出す。
- **リダイレクト**：`save-watched` は、条件を満たすときに `redirect("/trailers/:tmdbId")` を返す（`MyRecord` の fetcher はリダイレクトに従って画面を移る）。
- **ルールの更新**：CLAUDE.md の「スクレイピングをしない」「合意していない機能」の項目と、仕様書 013 の「やらないこと」の「AI による予告の認識」を、この仕様書に合わせて直す。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| AI に Web 検索させ、候補は TMDb で特定する | ○ | チャットで決定。アプリはスクレイピングせず、登録する作品は TMDb の情報になる |
| AI に TMDb の候補の一覧だけを渡し、Web 検索をさせない | × | 一覧のタイトルと公開日だけでは、「カーチェイスしていた」のような手がかりと結び付けられない |
| 1回の相談ごとに会話をリセットする | × | 思い出したことを足していけない |
| 検索結果のブロックも保存して送り直す | × | 費用が増え、記事の内容をアプリに保存することになる |
| ストリーミングで返答を少しずつ表示する | × | 1日数回しか使わない機能で、実装が増える。待ち時間の表示で足りる |

### 実装中に変えたこと（2026-11-23）
- **安全のための判定で断られたときの切り替え（server-side fallback）を有効にした。** Sonnet 5.5 は、安全のための判定で返答を断ることがある（`stop_reason: refusal`）。公式の推奨に従い、`fallbacks: "default"`（beta `server-side-fallback-2026-07-01`）を付け、そのときは Anthropic 側で別のモデルが続きを答えるようにした。映画の予告の相談で断られることはまずないので、費用への影響はほぼない。それでも断られたときは、AC6 の案内を出す。
- `output_config.effort` は `medium` にした（既定の `high` より、待ち時間と費用を抑えるため。精度が足りなければ上げる）。
- AI が失敗したときの action は、200 で `{ ok: false, error, message }` を返す（入力を消さずに案内を出すため）。入力の誤り（空、1,000文字超、探し終えた予告探し、キーが未設定）は 400。
- AI の候補のスナップショットは、D1 の1つの SQL に渡せる値の上限（100個）を超えないよう、90個ずつに分けて読む（`loadSnapshots`）。
- これまでの候補一覧の見出しを「候補」から「注目度の高い候補」に変えた（AI の候補と区別するため）。
- 仕様書 013 のテストで、「気になった予告」を1本以上にして保存したときの応答を、リダイレクト（302）を期待するように直した。
- 開発サーバーでの確認（AC10）は、`.dev.vars` に一時的に `ANTHROPIC_BASE_URL` を書き、手元のモックに向けて行った（実物の API は呼んでいない）。
