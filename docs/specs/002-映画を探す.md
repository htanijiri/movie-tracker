# 002 映画を探す（タイトル検索、公開中・近日公開の一覧）

- 状態：合意済み
- 依存：001

## 👤 ユーザーが確認するところ

### 何のための機能か
気になった映画を登録するには、まずその映画を見つける必要がある。タイトルを覚えていれば検索で、覚えていなければポスターの一覧を眺めて探せるようにする。

### できるようになること
- 「探す」画面で、タイトルの一部（例：「ゴジラ」）を入力すると、該当する映画がポスター付きで並ぶ。
- 同じ画面のタブで、「公開中」と「近日公開」の映画の一覧に切り替えられる。予告で見たがタイトルを思い出せない映画を、ポスターを見ながら探せる。
- 各映画には、ポスター、日本語タイトル、公開日が表示される。すでに自分が登録している映画には、その状態（劇場で見たい／サブスク待ち／視聴済み／見送り）が表示される。
- 映画を押すと、映画詳細（仕様書 003）に進む。
- 結果が多いときは「もっと見る」で続きを表示できる。

### データの扱い
- 映画の情報は TMDb から取得する（日本語、日本向けの情報）。入力した検索語は、このアプリのサーバーを経由して TMDb に送られる。
- ポスター画像は、ブラウザが TMDb の画像サーバーから直接読み込む。
- 「公開中」「近日公開」は TMDb に登録されている日本の公開日をもとにしているため、実際に近所の映画館で上映されているかどうかは分からない。

### 使い方の流れ
1. 下部のメニューから「探す」を開く。
2. タイトルを入力して検索する。または「公開中」「近日公開」のタブを選ぶ。
3. 目当ての映画を押して、詳細に進む。

### やらないこと
- 映画館ごとの上映スケジュールの表示（データの取得元がないため）。
- 予告を見た日付から候補を絞り込む機能（Phase 3）。
- ジャンルや出演者での絞り込み、成人向け作品の表示。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| タイトル検索に加えて、「公開中」「近日公開」の一覧も今回入れる | 出発点の「予告で見た作品名を忘れる」問題に、今回の範囲でも対応できる。作る量は少ない |

- 実装前に準備するもの：TMDb の API Read Access Token（仕様書 000 の準備と同じもの）
- 完成後に手で確認するもの：なし

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [ ] AC1：`/search?q=ゴジラ` の loader が、TMDb の `/3/search/movie` を `query=ゴジラ`、`language=ja-JP`、`region=JP`、`include_adult=false` で、`Authorization: Bearer <TMDB_ACCESS_TOKEN>` を付けて呼ぶ（自動テスト：fetch のモックで検証）
- [ ] AC2：loader の戻り値（＝ブラウザに渡るデータ）とレンダリングされた HTML に、トークンの文字列が含まれない（自動テスト）
- [ ] AC3：`/search?tab=now_playing` と `/search?tab=upcoming` が、それぞれ日本向けの公開中・近日公開の一覧を返す。近日公開は公開日の昇順で、今日より前の公開日の作品を含まない（自動テスト）
- [ ] AC4：結果の各要素に `tmdb_id`、タイトル、公開日、ポスターの URL（`https://image.tmdb.org/t/p/w342/...`。ポスターがない作品は代替表示）が含まれる（自動テスト）
- [ ] AC5：自分が登録済みの映画には、その状態のラベルが付く。他の利用者の登録は影響しない（自動テスト：D1 に2ユーザー分のデータを入れて検証）
- [ ] AC6：`page` パラメータで次のページを取得でき、最終ページでは「もっと見る」が出ない（自動テスト）
- [ ] AC7：検索語が空のときは TMDb を呼ばず、入力を促す表示になる。結果が0件のときは「見つかりませんでした」と表示する（自動テスト）
- [ ] AC8：TMDb が 5xx・429・タイムアウトを返したとき、アプリは 500 にならず、「映画情報を取得できませんでした。時間をおいて試してください」と表示する（自動テスト）
- [ ] AC9：実際の TMDb に対して、検索・公開中・近日公開が日本語タイトルで表示される（手動：Claude。開発サーバーとブラウザで確認）

### 設計方針
- **TMDb クライアント**（`app/lib/tmdb/`）：`searchMovies`、`listNowPlaying`、`listUpcoming`、`getMovieDetail`（003 で使用）。サーバー側だけで import する（`.server.ts`）。共通で `language=ja-JP`、`region=JP`、タイムアウト5秒。レスポンスは必要な項目だけに絞った型へ変換してから返す。
- **近日公開**：`/3/movie/upcoming` は期間の決まり方が TMDb 任せなので、`/3/discover/movie`（`region=JP`、`with_release_type=2|3`、`release_date.gte=今日`、`sort_by=primary_release_date.asc`）を使う。公開中は `/3/movie/now_playing`。どちらも実装時に実データで結果を確認し、合わなければこの節を直す。
- **キャッシュ**：Workers の Cache API に、TMDb の URL をキーとして保存する（検索・一覧は1時間）。キャッシュが使えない環境でも動くよう、失敗は無視する。TMDb の規約（6か月を超えて保持しない）の範囲内。
- **登録状態の付与**：結果の `tmdb_id` の一覧で `user_movies` を1回だけ引く（N+1 にしない）。
- **画面**：`/search`。上部に検索フォーム（GET）とタブ。結果はポスターのグリッド（スマホで3列）。「もっと見る」は `page` を増やしたリンク（JavaScript が無効でも動く）。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| サーバー側の loader から TMDb を呼ぶ | ○ | トークンをブラウザに出さない（BRIEF の方針） |
| ブラウザから TMDb を直接呼ぶ | × | トークンが露出する |
| 入力のたびに候補を出す（インクリメンタル検索） | × | TMDb への呼び出しが増える。Phase 1 では送信時の検索で足りる |
| TMDb の検索結果を D1 に保存 | × | 「TMDb の情報を大量にコピーしない」という BRIEF の方針に反する |

### 検証方法
- 自動テスト：TMDb のレスポンスを固定のフィクスチャ（架空の作品名で自作したもの。TMDb の実データはリポジトリに入れない）でモックする。
- 手動確認（Claude）：AC9。実際の TMDb の応答内容（日本語タイトルが入っているか、近日公開の並びが妥当か）は、モックでは確かめられないため。
