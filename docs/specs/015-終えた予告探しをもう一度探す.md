# 015 終えた予告探しをもう一度探す

- 状態：実装中（残りは AC6：ユーザーの確認）
- 依存：014

## 👤 ユーザーが確認するところ

### 何のための機能か
「探すのを終える」を押した予告探しは、今はどの画面からも開けず、開き直すこともできない。仕様書 013 の候補一覧で見つからずに終えた予告探しこそ、「AI に相談」（仕様書 014）で探し直したい。そこで、終えた予告探しを開いて、もう一度探せるようにする。

### できるようになること
- **映画の詳細画面から、その映画を見たときの「予告を探す」を開ける。**
  - 劇場で見て、「気になった予告」を1本以上にした映画の詳細画面に、「🎞 予告を探す」の入り口を出す。
  - 入り口には、探している途中か、終えたかを添える（例：`気になった予告 3本中 あと2本`、`探すのを終えました（3本中 1本）`、`3本をすべて見つけました`）。
  - 探している途中の予告探しも、ここから開ける。
- **終えた予告探しの画面に「もう一度探す」ボタンを出す。**
  - 押すと、探している途中の状態に戻る。トップページの「🎞 予告を探す」にもまた出て、「AI に相談」とこれまでの候補一覧が使える。
  - それまでに「これだった」で見つけた予告や、「違う」にした候補、AI との会話はそのまま残る。
  - 探し終わったら、これまでどおり「探すのを終える」でまた終えられる。
- 「気になった予告」をすべて見つけて終わった予告探し（例：3本中3本）には、「もう一度探す」は出さない。

### 使い方の流れ
1. 探し直したい映画の詳細画面を開く（トップページやリストから）。
2. 「🎞 予告を探す」を押し、「もう一度探す」を押す。
3. 「AI に相談」に覚えていることを書いて送る。あとは仕様書 014 と同じ。

### データの扱い・費用
- 新しく送るデータや、新しく使う外部サービスはない。
- AI に相談したときの費用と1日20回の上限は、仕様書 014 と同じ。

### やらないこと
- トップページに、終えた予告探しの一覧を出すこと。
- すべて見つけた予告探しを開き直すこと（「これだった」の取り消しも作らない）。見つけたい予告が増えたときは、これまでどおり「気になった予告」の本数を増やせば、また探せる。
- 終えた予告探しのまま（開き直さずに）、AI に相談できるようにすること。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 終えた予告探しは、映画の詳細画面から開く。トップページには一覧を出さない | 探し直したい映画は覚えているはず。トップページを長くしない |
| 終えた予告探しの画面の「もう一度探す」で、探している途中の状態に戻す | 戻したあとは、AI への相談も候補一覧も、これまでと同じ操作で使える |
| すべて見つけて終わった予告探しは、開き直せない | 探すものが残っていない |

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [x] AC1：映画の詳細画面の loader が、その映画の予告探し（`getTrailerHunt`）を返し、予告探しがあるときだけ `/trailers/:tmdbId` へのリンクを出す。リンクには進み具合（途中／終えた／すべて見つけた）を添える。見ていない・劇場以外・本数が0か未入力の映画には出さない（自動テスト）
- [x] AC2：終えた予告探し（`trailer_hunt_closed_at` があり、見つけた本数が本数未満）の画面にだけ「もう一度探す」（`intent=reopen`）を出す。探している途中・すべて見つけた予告探しには出さない（自動テスト）
- [x] AC3：`intent=reopen` で `trailer_hunt_closed_at` が空になり、トップページの一覧（`listOpenTrailerHunts`）に戻り、「AI に相談」（`intent=ask`）を受け付ける。「これだった」「違う」と AI の会話は残る（自動テスト）
- [x] AC4：すべて見つけた予告探し・探している途中の予告探しへの `intent=reopen` は 400 で、データは変わらない。ほかの利用者の予告探しは 404（自動テスト）
- [x] AC5：開発サーバーで、映画の詳細画面のリンクから終えた予告探しを開き、「もう一度探す」を押すと、「AI に相談」の欄と候補一覧が出る。幅 375px で横スクロールが出ない（手動：Claude）
- [ ] AC6：本番で、仕様書 013 の確認のときに終えた予告探しを映画の詳細画面から開き、「もう一度探す」を押して、AI に相談できる（手動：ユーザー）

### 設計方針
- `app/lib/trailers.server.ts` に `reopenTrailerHunt(db, userId, visitTmdbId)` を足す。`user_id`・`tmdb_id` で絞り、`trailer_hunt_closed_at` を NULL にする。
- `getTrailerHunt` は、`closed`（終えた、またはすべて見つけた）に加えて、`reopenable`（`closedAt` があり、見つけた本数が本数未満）を返す。
- `app/routes/trailers.tsx` の action に `reopen` を足す。`reopenable` でなければ 400。画面は、`reopenable` のときに進み具合の下へ「もう一度探す」ボタンを出す。
- `app/routes/movie.tsx` の loader で `getTrailerHunt` を呼び、`MyRecord` の下に入り口のリンク（`TrailerHuntLink`、`data-hunt-link`）を出す。進み具合の文言は `trailers.tsx` と共通の関数にする。
- DB のスキーマは変えない（マイグレーションなし）。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 映画の詳細画面から開く | ○ | 探し直したい映画は覚えている。トップページを長くしない |
| トップページに終えた予告探しの一覧を出す | × | トップページが長くなる（ユーザーの回答） |
| 終えたまま AI に相談できるようにする | × | 開き直せば、これまでの操作（候補一覧、「探すのを終える」）がそのまま使える（ユーザーの回答） |
